# Native UI contract

`src/contract.json` is the complete mounted OpenAPI path/model projection plus actual Config defaults, generated by `tools/export_contract.py`. It is checked against a real disposable FastAPI mount in `test_native_ui.py`. No route or request model is invented by the UI. The UI uses the injected instance API; all plugin paths are prefixed with the current `pluginId`.

## W10B read-only additions

| Method / route | Response | Scope |
|---|---|---|
| GET `/archive/scans/{scan_id}/items` | Existing `Page[Row]` | Authenticated admin; exact persisted scan ID; limit 1..100 (default 25), nonnegative offset; missing scan 404. Row id and data.item_id identify an existing scan item for the existing mapping-test action. Data contains only scan_id, item_id, service, library. PENDING means resolved is NULL; PROCESSED means the scan recorded a result (including an empty result), not that mapping or ingestion succeeded. No raw media path/payload is returned. |
| GET `/diagnostics` | Existing `Health` | Adds services.local_rules with bounded configured runtime rule id, revision, enabled. The revision is from the actual delivery worker, not a checkpoint or reconstructed config. Selecting a rule supplies component=local, object_id and revision to the existing fenced POST /health/reconcile. |

Both reads use existing authorization/boundary/public projection semantics. The new page uses the existing SQLite read snapshot and server pagination. No database schema, worker, delivery action, clock or mutation semantics change. `foundation_only=false` now identifies the complete native implementation; it does not claim a deployment or real cloud/Emby acceptance.

The unchanged A1/A2/A3 backend validates all other actions. A3 mutation sends only preview_id, preview_digest, operation_id, confirm. Config performs one preflight and one exact save emit; only the parent performs its native full PUT. Dedicated migration/credential writes keep private drafts outside ordinary config and exports.
