# ChatGPT Plus Ultra 1.4.2

面向 MoviePilot V2 的保守型辅助名称提取器。AI 只返回两个字符串字段 `name/year`；插件验证后，使用 MP2 对**当前标题**的原生解析结果传递 NameRecognize 事件需要的季集。插件只提供名称候选，不替代媒体库匹配，不调整字幕、画质、站点或洗版规则。

## 1.4.2：别名误拒绝与诊断修正

### 电影版标记只约束被选中的名称来源

不再因为输入的任意别名出现 `The Movie`，就要求合法中文名也包含该词。例如：

```text
The Stain 2026 [污点 / Buppha the Movie / The Stain]
```

返回 `{"name":"污点","year":"2026"}` 可以通过这项校验。校验仍要求名称能在输入找到文字依据，不利用模型记忆创造译名。

匹配来源时优先括号内的文字，再检查括号外的原始名称；同一优先级按出现顺序选择首个匹配片段。片段以括号和 `/`、`／` 划分，冒号后的副标题不会被拆成另一个别名。

以下保护仍然保留：

- `[命运石之门剧场版：负荷领域的既视感]` 不能缩成 `命运石之门`。
- `Steins;Gate.the.Movie` 不能通过删除 `The Movie` 变成系列总名。
- `[剧场版][命运石之门]` 等紧邻、独立的电影版标签仍受保护。
- 较短的括号外名称不能覆盖同名、明确带电影版标记的括号来源。
- 来源边界破损或无法定位时保持保守拒绝，不把解析不确定性当成放行依据。

这仍是文本证据规则，不是数据库身份验证，也不保证覆盖所有合法别名。

### 同名同年份不再与普通候选混为一谈

交付给 MP2 的名称、年份与插件本次 `MetaInfo(title)` 一致时，记录：

```text
status=submitted reason=unchanged_current_title source=api
name="最后的同意书" year=null
```

DEBUG 另有 `identity_scope=current_title`。名称比较遵循 V2 对返回名称的点号替换规则，年份使用最终回填值，而不是未经适配的 AI 空字符串。

**这只是诊断，不是主程序的 no-effect 判决。** MP2 只把 `title` 传入此事件，插件看不到调用方完整的 `org_meta`。原始路径、副标题或父目录继承的元数据可能不同。因此：

- 仍提交经过验证的候选，由主程序决定是否重查。
- 不因为当前标题比较相等而提前返回或改写主程序重试计数。
- 合法候选继续使用正缓存，不作为“失败”写入短期负缓存。
- 比较在每次回填时重新执行，不能缓存第一次调用的“无变化”结论。

这项改动不会减少首次 API 调用。它避免把没有可见名称增量的输出表现成新增识别信息，同时不阻断可能有用的主程序匹配。

### 缓存与季集范围不扩张

本版**不新增跨画质身份缓存**，继续保留完整标题缓存和同标题并发合并。不同技术规格的标题仍可能各调用一次 API；同一标题在有效期内复用缓存。没有重新删除括号、季集或版本词来追求命中率。

本版**不修改季集解析或传递逻辑**，不增加另一套季集正则，不动态替换 MP2 方法。原生解析器的数字误判不在本次修复范围内；没有进入 NameRecognize 的资源也不受本插件影响。

## 提示词、协议与升级

默认提示词仍只允许 `name/year` 两个字符串字段，未知年份用 `""`，不能识别用 `{"name":"","year":""}`。模型不输出 `title/season/episode/media_type/confidence`。插件事件中额外的 `title/season/episode` 是另一层主程序接口，空年份在这里转为 `None`，日志显示 `null`。

1.4.2 默认提示词澄清了独立别名的标记边界，并增加“污点”的提取示例。旧的 1.4.0/1.4.1 内置提示词会在初始化或保存时迁移，原文备份到 `previous_customize_prompt`；用户另行修改的自定义提示词不强行替换。原有已知旧模板迁移、空值恢复和手动“保存时恢复新版默认提示词”仍保留。校验协议版本已更新，防止沿用旧规则生成的缓存标识。

更新到 **1.4.2** 后保存一次配置。API、模型、代理、缓存时长等既有设置不被强制替换。继续使用现有 DeepSeek 配置；默认模型 ID 为 `deepseek-flash`，请求配置为 DeepSeek 时发送非思考模式和辅助识别 JSON 模式参数。不传联网工具，不在本次修改中改变请求参数或服务商重试行为。

## 日志与统计

- INFO：实际 API 调用产生且已交付的新候选，包含关联 ID、name/year、来源和耗时；无可见增量时使用 `unchanged_current_title`。
- DEBUG：脱敏、截断至 480 字符的标题，AI 的 name/year、本次 MetaInfo 的 name/year、最终回填字段、请求次数、服务商返回的 Token 数和原因。`season_episode_source=MetaInfo` 只表示来源，不保证解析正确。
- WARNING：服务错误分类、可用 HTTP 状态码、密钥编号，及结构/语义拒绝原因；同类提示 300 秒去重。明确放弃不是密钥错误。

`source=api` 表示真实 HTTP 请求；`cache` 为本地复用；`coalesced` 为等待同标题进行中的请求；`local` 为本地跳过或冷却。重复缓存提交只写 DEBUG。关联 ID 在相同标题/配置内稳定，不是每次调用唯一的请求编号。使用 MP2 logger，插件日志仍由主程序独立路由。

不输出配置密钥、Authorization/Cookie 原文、原始模型响应、服务端错误正文或聊天回复；标题中的 URL 整段隐藏，控制字符清理后以单行 JSON 转义。普通片名仍可见，不是匿名日志；第三方依赖自己的日志不由本插件全局修改。

详情页保留真实 HTTP 次数、校验结果分布、缓存和冷却统计。`validation_results.accepted` 指结构/内容通过，不能当成主程序最终匹配成功率或名称变化率。只累计真实响应明确给出的非负整数 Token 字段，缓存不重复累计；服务商提示词缓存不是插件本地缓存，用量统计不等于账单。

## 缓存、错误与生命周期

完整标题、接口、模型、有效提示词和校验协议版本参与缓存标识。默认有效候选缓存 3600 秒、负缓存 600 秒、容量 1000 条、请求并发 2，均可配置。缓存为实例内存缓存；重启或保存配置重建；清理时旧请求不能重新填回已清空的缓存。

只有明确 401 才禁用对应密钥并有限轮换；429、网络、超时及配置错误分别冷却，不以切换密钥绕过限流；较短的并发错误不缩短既有 Retry-After。识别无名称或校验不通过不封禁密钥。配置重载后旧请求不能继续回填，已开始的 HTTP 结束后释放客户端。

默认 20 秒预算包含排队和鉴权轮换；HTTPX 读写超时不是严格总墙钟期限，持续缓慢传输仍可能超出。依赖继续为 MP2 提供的 HTTPX，不升级共享 OpenAI SDK。聊天按渠道/用户隔离并限制历史，本版不扩展聊天功能。

## MP2 源码与边界

本次重新读取 V2 分支，HEAD 仍为 `6a02e7de21c110d758e3fc44e79150ac1d4d7949`，`app/chain/media.py` blob 为 `2c17871a2f42454685c7069ad2bdb6f63f658682`；与此前对照的 `v2.15.6` 一致。仍使用 V2 的 `recognize_help` / `async_recognize_help`、`MetaInfo` 与 `app.log.logger`，未改成 V3 接口。

主程序名称/年份相同会提前返回；发生变化后覆盖起始季集，任一季集非 None（包括 0）会设为 TV。两个 None 不会强制把既有 TV 改回电影；原调用方完整元数据不可见；没有最终匹配反馈接口。这些限制均未宣称修复。建议只开启一个 AI 名称提供者，本插件尊重已有有效结果，但不能阻止后续插件覆盖。
