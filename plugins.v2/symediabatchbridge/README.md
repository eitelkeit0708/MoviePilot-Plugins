# Symedia 批次移交 · MoviePilot V2

MP 负责下载、整理；本插件将视频和外置字幕上传到 115，核对齐套后，通过 CD2 把**一个完整批次目录**移入 Symedia 的待归档目录。Symedia 继续负责归档、改名、STRM 和媒体库通知。

这是独立的 V2 插件，仅使用 MP 内置 115，不依赖 DDSRem 或 subscriBetter，也不修改 MP 或其他插件的方法。当前版本 `1.1.0`。

## 配置前准备

1. 在 MP 的存储设置中登录内置 115（`u115`）。本插件直接沿用其授权，不需要安装额外的 115 储存插件或 STRM 助手。**是否命中由 115 返回结果决定，不能保证每个文件都秒传。**
2. MP 将下载内容复制或硬链接到一个实际的本地整理目录。移交完成前保留下载器任务和下载记录；插件需要读取下载器当前选中的视频、音频和字幕清单来判断是否齐套。
3. CD2 挂载与上述储存相同的 115 账号，创建独立的暂存目录和 Symedia 待归档目录。这两个目录不能互相包含。
4. Symedia 仅监控待归档目录，并能递归处理下面的批次目录。**不要监控暂存目录。**相同本地目录不要再配置另一条自动上传任务。
5. 本插件直接使用 CD2 gRPC API；不需要安装 MP 的 CD2 储存插件。CD2 API 令牌需要有读取、移动这些目录的权限。

## 路径示例

| 配置项 | 示例 | 含义 |
| --- | --- | --- |
| MP 本地整理目录 | `/media/organized` | MP 容器内的路径 |
| 115 暂存目录 | `/MP暂存` | 相对于 115 根目录的路径 |
| CD2 中的 115 挂载目录 | `/115` | CD2 API 看到的挂载根路径 |
| Symedia 待归档目录 | `/115/Symedia待归档` | CD2 API 路径，不是容器挂载的本地路径 |
| CD2 gRPC 地址 | `http://cd2:19798` | MP 容器能访问的 CD2 地址；支持 HTTPS |
| CD2 API 令牌 | 在配置页填写 | 不会出现在插件详情页或处理记录中 |
| 检查间隔 | `1` 分钟 | 插件队列检查周期，与 PT 站点访问无关 |

文件路径保持为：

```text
本地整理目录/
└── 电视剧/同名剧 (2026)/Season 01/
    ├── 同名剧 S01E01.mkv
    └── 同名剧 S01E01.zh.ass

115 暂存目录/
└── symediabatchbridge-<唯一批次ID>/
    └── 电视剧/同名剧 (2026)/Season 01/
        ├── 同名剧 S01E01.mkv
        └── 同名剧 S01E01.zh.ass

CD2 整目录移动后：
/115/Symedia待归档/
└── symediabatchbridge-<同一个批次ID>/
    └── 电视剧/同名剧 (2026)/Season 01/...
```

不同下载任务即使作品、季、目录同名，也使用不同的外层批次目录。作品目录和视频、字幕文件名不会被添加随机后缀。最终媒体库中的版本覆盖或合并仍由 Symedia 的归档规则决定。

## 秒传等待

每个文件独立执行：**立即尝试 → 未命中后等 1 小时 → 最多 24 次 → 最后一次未命中再等 1 小时 → 普通上传**。视频、音频和字幕使用同一规则。

- 连续正常运行时：第 0 小时第 1 次，第 23 小时第 24 次，最早第 24 小时普通上传。实际执行由队列检查调度，可能稍晚。
- 任意一次秒传成功，该文件立即完成，不再重试。一个文件在等待时，其他文件继续尝试；所有文件完成并核对通过才整目录移交。
- 登录失效、网络错误、未知响应不算“未命中”，一小时后重试，不会因为报错而提前普通上传。因此故障或停机可能让总等待时间超过 24 小时。
- 次数和下次时间写入批次数据库；重启、停用再启用、点击“重新检查”均不重置。停机期间漏掉的尝试不集中补发。
- 详情页显示每个待完成文件的未命中次数、下次时间和下一步操作。等待期间保留本地文件、MP 下载记录和下载器任务。
- 升级后的未上传文件从首次秒传尝试开始计时；已有上传回执及目录移交记录保留。不重复发送已完成文件。
- v1.0.0 中使用 DDSRem 接口的旧批次暂停等待确认。在详情页确认 MP 内置 115 与 CD2 使用同一账号后切换，保留已有文件和回执；目录映射同时变化时不能切换，需要先恢复原目录。新批次直接使用 MP 内置 115。

秒传阶段只调用上传初始化及必要的哈希校验，不获取 OSS 上传凭证、不发送完整文件内容。普通上传阶段才调用 `StorageChain.upload_file`，其内部仍可能再次秒传。

## 运行与恢复

- **首次启用**：只接收之后的 MP 整理记录，不扫描整个旧媒体库。后续重启或停用再启用，会从已有检查位置恢复。
- **批次范围**：一个下载器任务对应一个批次，依据下载器选中的媒体/字幕清单及 MP 成功整理记录核对。未选中的文件不加入。已明确关联同一任务的额外字幕整理记录也会加入。
- **等待齐套**：选中的字幕尚未下载、尚未整理、整理失败，或文件缺失时，整批等待。不会用“目录几分钟没变化”代替完成依据。
- **上传**：第一次准备上传时固定文件清单、相对路径、大小、SHA1 和前缀哈希，逐个记录回执。后续小时重试复用哈希；每次上传前后检查本地文件是否变化。
- **核对**：通过 CD2 强制刷新并递归读取该批次，对照完整文件集合和大小；CD2 返回 SHA1 时也会比对。多出的文件、内容不符、文件选择变化均停止移交。
- **整目录移交**：先持久化移动意图，再调用一次 `MoveFile`，只传入外层批次目录。设置同名冲突为 `Skip`，禁止跨云盘移动和递归合并。
- **重启或响应丢失**：保持同一批次 ID。上传回执丢失时，仅在云端文件 SHA1、大小均相符时接续。移动回执丢失时只核对结果；源和目标都不见时可能已被 Symedia 消费，会提示人工核对，不重新上传或移动。
- **后到文件**：固定清单之后出现新附件会暂停；移交之后出现新的关联整理记录会提示“后续变更”。不会自动单独补送字幕，也不会重发整部视频。
- **重新检查**：修复下载器、文件、目录映射或连接后，在插件详情页点击。它保留原批次及回执，不等于删除旧任务重新发送。
- **停用/改配置**：停止发起新操作；已经进入储存提供者的单文件上传可能继续完成。完成后旧工作进程不会发起目录移动；文件锁防止新旧实例同时处理同一队列。进行中的批次不会随目录配置变化而改投别处。

每次调度最多处理 3 个到期批次。秒传未命中和秒传接口错误按上述每文件一小时间隔处理，不消耗批次失败次数。其余阶段的临时错误按 1、2、4、8、16、30 分钟退避，10 次后转为“需要处理”。单纯等待 MP 下载/整理完成不消耗失败次数。详情页显示原因、下次检查时间和重新检查入口。普通上传速度和单文件超时由 MP 储存提供者管理。

## 当前支持边界

- 适用于有 MP 下载记录、下载器任务清单和逐文件整理记录的普通影音文件及外置字幕。MP 的自动订阅下载和手动搜索下载均可走这条链路。
- 没有下载任务标识的手工导入、BDMV 整目录原盘，以及无法关联到任务的外来字幕不自动交付。选中但被 MP 排除整理的样片等也会等待，需要先在下载器或 MP 中处理相应文件选择/整理问题。
- 不等待未来可能下载的字幕；只对本次已知清单负责。一个已交付的种子任务之后再选择新集数或更换附件，不会自动形成第二批。
- 保留的是本批媒体与字幕相对于整理根目录的目录结构；不镜像整个媒体库，不上传 MP 之后异步刮削产生的 NFO、海报等。元数据文件交给 Symedia 生成。
- 不修改 MP 订阅、PT 站点访问、搜索或 RSS 流控；不修改其他插件的上传队列；不删除本地文件和暂存数据；不直接通知 Emby。
- 详情页“已移交”仅表示 CD2 确认移动，**不表示 Symedia 已完成归档或 Emby 已入库**。单个目录移动请求及预先齐套核对，仍需在实际 CD2/Symedia 的监听方式下验证可见性和处理结果。
- 批次回执位于 MP 插件数据目录下的 `SymediaBatchBridge/batches.sqlite3`。请持久化整个 MP 配置/插件数据目录；回执丢失可能导致无法识别已经处理过的任务。不要为了重试而删除记录。

## 安装与验收状态

源文件目录为 `plugins.v2/symediabatchbridge/`，索引为根目录 `package.v2.json` 中的 `SymediaBatchBridge`；依赖在插件自身的 `requirements.txt`。在 MP V2 插件市场添加本仓库后安装或更新，由 MP 安装依赖、管理启停和配置。升级时保留已有插件数据目录，以继续使用批次回执、文件 HASH 和重试进度。

开发核对的源码版本：

- MP V2：[`1528176`](https://github.com/jxxghp/MoviePilot/tree/1528176beacc0f9f8d8d9cbf1adf048b0da67b5c)，使用公开的 `DownloadChain`、`StorageChain`、`DownloadHistoryOper`、`TransferHistoryOper`，未使用宿主私有上传队列。
- MP 前端 V2：[`19cead0`](https://github.com/jxxghp/MoviePilot-Frontend/tree/19cead06f72c859732afdeccea7a37c0a770a947)，按 `PageRender` 的 JSON POST 请求和页面刷新约定接入按钮。
- [CD2 API 指南](https://www.clouddrive2.com/api/CloudDrive2_gRPC_API_Guide.html)，客户端 `clouddrive2-client==0.3.0`。

离线测试包括真实插件命名空间加载、字幕等待、重名隔离、上传/移动丢失回执恢复、停用并发锁、路径与清单保护、原生 MP 路由注册和 CD2 实际 protobuf 请求。测试替换了 MP 数据库、下载器、115、CD2 服务端；这些测试不能代替真实服务验收。

秒传适配集中在 `instant.py`：原生 115 复用 `U115Pan._request_api` 的授权、请求与限流，仅调用 `/open/upload/init`。宿主的低层方法并非稳定公共 Chain 合同，升级兼容性必须继续验证；方法缺失或响应不符合已知合同会停止/等待，不会回退普通上传绕过等待。没有替换、补丁或重写宿主方法。
