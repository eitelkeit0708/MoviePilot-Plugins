# 115秒传助手 · MoviePilot V2

MP 负责下载、整理；本插件将视频和外置字幕上传到 115，核对齐套后，通过 CD2 把**一个完整批次目录**移入 Symedia 的待归档目录。Symedia 继续负责归档、改名、STRM 和媒体库通知。

这是独立的 V2 插件，仅使用 MP 内置 115，不依赖 DDSRem 或 subscriBetter，也不修改 MP 或其他插件的共享对象。当前版本 `1.6.0`。原名“Symedia 批次移交”；内部 ID `SymediaBatchBridge` 和数据库路径不变，升级保留待处理批次、HASH 和秒传进度。

## 从旧版升级

直接更新原插件，保留 MP 配置和 `SymediaBatchBridge` 数据目录，无需卸载、重新配置或重新接管。单路线旧配置、三路线配置及原批次的目录映射继续有效；本地清理仍沿用该批次原先记录的选择，旧记录没有此选项时不会自动删除文件。

- 已有批次 ID、SHA1、上传回执、秒传次数及下次时间、共享冷却、接收队列和通知记录保留；已上传文件核实后跳过，已移交批次不会重传。
- 已保存完整媒体范围且全部文件已计算 HASH 的旧批次，自动补全接管信息。升级期间收到的新字幕在确认接收前加入清单，保留既有整理记录 ID。
- 仅完成部分 HASH 或缺少完整范围证据的旧批次，不会根据剩余几个文件猜测齐套，继续按原来源核实；显式接管过的存量文件使用已有快照。
- 已发出的整目录移动按原路径和回执继续核对；旧的本地清理隔离记录可以恢复，即使下载源已正常到期删除。升级不会开启原先关闭的本地清理。

## 配置前准备

1. 在 MP 的存储设置中登录内置 115（`u115`）。本插件直接沿用其授权，不需要安装额外的 115 储存插件或 STRM 助手。**是否命中由 115 返回结果决定，不能保证每个文件都秒传。**
2. MP 将下载内容复制或硬链接到实际的本地整理目录，推荐继续使用硬链接，避免额外复制 I/O。每个目的地设置一张路线卡，最多 16 条，本地整理目录不能相同或互相包含。完整接管前保留下载器任务及整理记录，以核实所选视频和字幕齐套；日志出现“完整清单已接管”后，以持久化清单和整理副本为准，允许做种源和下载任务正常到期删除。
3. CD2 挂载与上述储存相同的 115 账号，创建独立的暂存目录和 Symedia 待归档目录。这两个目录不能互相包含。
4. Symedia 仅监控待归档目录，并能递归处理下面的批次目录。**不要监控暂存目录。**相同本地目录不要再配置另一条自动上传任务。
5. 本插件直接使用 CD2 gRPC API；不需要安装 MP 的 CD2 储存插件。CD2 API 令牌需要有读取、移动这些目录的权限。令牌根目录设置为整个 115 盘时，插件中的 CD2 根目录填写 `/`，待归档路径使用 `/transfer/...`；令牌根目录为 CD2 总根时，填写 `/115` 和 `/115/transfer/...`。不要使用只授权了某个无关子目录的令牌。

## 路径示例

| 配置项 | 示例 | 含义 |
| --- | --- | --- |
| MP 本地整理目录 | `/media/organized` | MP 容器内的路径 |
| 115 暂存目录 | `/MP暂存` | 相对于 115 根目录的路径 |
| CD2 中的 115 挂载目录 | `/115` | CD2 API 看到的挂载根路径 |
| Symedia 待归档目录 | `/115/Symedia待归档` | CD2 API 路径，不是容器挂载的本地路径 |
| CD2 gRPC 地址 | `http://cd2:19798` | MP 容器能访问的 CD2 地址；支持 HTTPS |
| CD2 API 令牌 | 在配置页填写 | 不会出现在插件详情页或处理记录中 |
| 检查间隔 | `1` 分钟 | 插件队列检查周期，与 PT 站点访问无关 |

三条路线可以这样配置（示例采用令牌根目录为 115 盘、CD2 根目录填 `/`）：

| 路线 | MP 本地整理目录 | 115 暂存目录 | Symedia 待归档目录 |
| --- | --- | --- | --- |
| 入库 | `/media/organized/complete` | `/MP暂存/入库` | `/transfer/LYZ` |
| 追更 | `/media/organized/updating` | `/MP暂存/追更` | `/transfer/115upload` |
| 涂佩 | `/media/organized/tupei` | `/MP暂存/涂佩` | `/transfer/tupei` |

连接和令牌共用，三个最终归档目的地继续由 Symedia 的对应规则决定。添加、移除、修改路线只影响之后新建的批次；已入队批次保留原目录，继续使用更新后的令牌。改动 CD2 主机或挂载根时旧批次会暂停，避免送往另一账号。新旧路线的任何暂存目录均不能落入其他路线的待归档目录。

文件路径保持为：

```text
本地整理目录/
└── 电视剧/同名剧 (2026)/Season 01/
    ├── 同名剧 S01E01.mkv
    └── 同名剧 S01E01.zh.ass

115 暂存目录/
└── symediabatchbridge-<唯一批次ID>/
    └── 电视剧/同名剧 (2026)/Season 01/
        ├── 同名剧 S01E01.mkv
        └── 同名剧 S01E01.zh.ass

CD2 整目录移动后：
/115/Symedia待归档/
└── symediabatchbridge-<同一个批次ID>/
    └── 电视剧/同名剧 (2026)/Season 01/...
```

不同下载任务即使作品、季、目录同名，也使用不同的外层批次目录。作品目录和视频、字幕文件名不会被添加随机后缀。最终媒体库中的版本覆盖或合并仍由 Symedia 的归档规则决定。

## 秒传等待

每个文件独立执行：**立即尝试 → 未命中后等 1 小时 → 最多 24 次 → 最后一次未命中再等 1 小时 → 普通上传**。视频、音频和字幕使用同一规则。

- 连续正常运行时：第 0 小时第 1 次，第 23 小时第 24 次，最早第 24 小时普通上传。实际执行由队列检查调度，可能稍晚。
- 任意一次秒传成功，该文件立即完成，不再重试。一个文件在等待时，其他文件继续尝试；所有文件完成并核对通过才整目录移交。
- 登录失效、网络错误、未知响应不算“未命中”，一小时后重试，不会因为报错而提前普通上传。因此故障或停机可能让总等待时间超过 24 小时。
- 次数和下次时间写入批次数据库；重启、停用再启用、点击“重新检查”均不重置。停机期间漏掉的尝试不集中补发。
- 详情页显示每个待完成文件的未命中次数、下次时间和下一步操作。等待期间保留本地整理文件；完整接管前还需要下载器清单和 MP 整理记录，接管后不再依赖做种源、下载任务或旧整理历史。显式接管的存量批次使用已记录的文件快照。
- 升级保留已有秒传计时；只有尚无秒传记录的旧文件从首次尝试开始计时。已有上传回执及目录移交记录保留，不重复发送已完成文件。
- v1.0.0 中使用 DDSRem 接口的旧批次暂停等待确认。在详情页确认 MP 内置 115 与 CD2 使用同一账号后切换，保留已有文件和回执；目录映射同时变化时不能切换，需要先恢复原目录。新批次直接使用 MP 内置 115。

秒传阶段只调用上传初始化及必要的哈希校验，不获取 OSS 上传凭证、不发送完整文件内容。普通上传阶段复用 MP 内置 `U115Pan.upload` 算法，其内部仍可能再次秒传及重新计算 HASH。

### 115 共享冷却

插件所有路线共用一个持久化的 `u115` 冷却截止时间。HTTP 429 或 MP 已识别的业务访问上限会停止本轮后续云端操作，按 MP 冷却时长等待；`Retry-After` 更长时延长等待。重启、改配置、手动重新检查均不会清空冷却。已有 MP 冷却也会被继承。冷却期间可继续本地 HASH，暂停插件发起的目录查询、创建、上传及 CD2 核对/移交。

鉴权、网络、服务端故障和未知响应分别记录，均不计秒传未命中；已发起但未确认结果的秒传仍保留一小时间隔。普通上传只能由 24 次明确未命中及完整等待时间授权。

请求层复用 MP 当前登录会话、登录刷新与 QPS 限速。目录及普通上传仅在一个私有提供者副本中替换请求入口，以取得原始 HTTP 状态；原 MP 单例、类及会话方法保持原样。针对原生方法签名和请求路径检查兼容性，未知接口停止执行。该冷却管控本插件各路线，不能限制 MP 其他模块或独立 CD2/Symedia 的所有请求；已经开始的原生 OSS 上传仍不能强制取消。

## 运行与恢复

### 日志、处理记录与通知

通知复用 MP 整理记录中的作品、年份、类型、海报和季集，不额外查询 TMDB。成功通知显示本次实际移交的季集与文件；异常、转普通上传通知定位对应文件。多集清单保留缺集和跨季范围，字幕不重复计集；海报缺失时照常发送文字，多作品批次不套用单部作品的海报。通知内容随事件持久化，提交重试不改变当时的媒体范围。升级不补发已成功提交的旧通知；未完成旧批次在下次核对文件时补齐媒体信息。

页面按作品显示紧凑的进度列表，支持路线及“需关注 / 处理中 / 已移交 / 已终止”筛选。异常在数据库分页之前置顶；点击“处理异常”查看原因、对应处理步骤和下一次自动检查时间。可按情况重新检查、删除孤立字幕或终止批次；云端移动结果未知时仍提供归档核对入口。已移交但本地清理失败的批次不会提供重新上传入口。重新检查只排队，核实前保留原异常，不清空清单、HASH、回执、秒传次数或共享冷却。

“完整记录”保留本地/暂存/移交路径、MP 整理 ID、全部文件及 SHA1、秒传未命中次数、下一次操作和分页时间线。尚未封存的存量批次也能查看已知文件路径。“运行与目录”集中显示检查结果和目录配置；“现存文件”用于查看只读扫描结果并选择接管。海报复用 MP 已保存信息，缺失时显示媒体图标。升级前的旧过程不会伪造补写；之后的记录持续保存。

启停、接收批次、HASH 完成、每次秒传结果、普通上传、云端核对、目录移交、异常恢复和副本清理写入 MP 插件独立日志 `symediabatchbridge.log`；MP 主日志没有这些条目是正常的。空闲检查每小时记录摘要，页面的检查时间每轮更新；同一等待条件不每分钟刷日志。

大文件开始读取前即显示“计算 HASH”和当前文件，读取时最多每 5 秒保存进度，刷新列表或详情可见已读大小、百分比和更新时间；长时间计算每分钟记录一次进度。这个进度表示本地文件读取，不是上传进度。只有完整 HASH 校验结束才保存该文件摘要；中断时保留已完成文件 HASH，未完成的单个文件重新计算。

通知使用 MP 原生 `post_message(mtype=NotificationType.Plugin)`，沿用宿主的“插件”消息渠道、接收人、消息历史和插件详情链接。覆盖移交成功、首次处理异常、达到 24 次未命中并结束等待后的普通上传开始；普通上传完成记录到文件时间线，全部文件移交后再发批次成功通知。持续同一批次异常最多每日提醒一次，转普通上传每文件一次。日志/消息不包含令牌、SDK 原始异常或认证 URL。

通知意图与批次状态在同一 SQLite 事务中保存。提交失败按 1–30 分钟退避，成功批次的待发通知也会继续处理；重启不丢失。MP 的接口没有外部渠道送达回执，因此页面写“已提交 MP”，不宣称手机已收到；若进程在 MP 接收后、保存提交回执前退出，恢复时可能重复一次通知。

通知由独立的 MP 服务每 5 秒检查待发队列，不再在 HASH、上传或状态保存时同步发送。跨重载的通知文件锁一直保留到正在执行的发送返回，避免旧实例还在发送时新实例重复派发；它不占用媒体处理锁。

MP 整理事件先写入独立的 SQLite 接收队列，保存当时的路线与清理选项，大文件处理期间也能接收。页面显示待纳入批次的记录数；媒体工作者在安全边界读取记录并建立批次。重复事件去重，读取失败自动重试，重启不丢失。后到事件和历史补读不会越过尚未解析的先到事件，避免同一种子在修改设置后采用错误路线或清理选项；已经入队的媒体任务继续运行。连续两次读取失败后，用完整历史核对，确认已删除的记录保留快照并单独显示；读取失败不会被当成空历史。

### 一次性存量处理与可选清理

正常运行只接收首次启用后的整理记录。“检查现存文件”是只读检查，扫描所有路线当前文件，关联其最新 MP 整理记录，列出可接管批次和未接管文件。不会仅因为存在旧整理记录就接管已经不存在的文件。页面可单独接管一个批次。

配置中的“保存后处理一次现存文件”默认关闭。开启并保存后，先持久化请求并复位开关，在下一轮检查执行一次；重启后恢复尚未完成的请求。保存时立即记录接收日志，数据页顶部显示排队、执行、完成或重试状态及实际接管数量。已接管批次按下载器及任务标识去重；无可用整理关联、原盘等不支持类型列出原因。

存量处理以整理目的地当前存在的文件为准：首次扫描关联最新成功 MP 整理记录，保存路径、记录 ID、媒体信息、大小、修改时间、设备与文件身份，再核算 HASH。原下载源、做种任务已删除也可上传，不会调用 MP 再整理。接管后不再依赖旧整理历史；历史删除、重建不会让文件失效。实际文件缺失或内容变化仍暂停，只剩字幕的批次不移交。旧版已全部封存且完整范围可核实的批次自动迁移，保留 HASH 与上传回执；尚无完整清单的旧普通批次不能凭剩余几个文件猜测齐套。

接管范围来自明确清单，不扫描猜测文件是否被移动，也不能判断其他工具是否曾经上传过它。移交前收到的同一任务成功整理事件可以追加文件，原文件身份不被覆盖；移交前再接收一次排队事件，尚未解析的事件会暂缓移交。未来尚未发生的整理不能预知，应在 MP 整理完成后接管存量。

“移交后删除本地整理副本”默认关闭，仅作用于之后接管的批次。必须已确认移交、保有逐文件上传回执，且整理副本仍是接受的文件才清理；不要求做种源存在或硬链接计数至少为 2。复制整理也适用。逐文件保存隔离意图、隔离后复核身份再删除，重启后继续，不操作下载目录或下载任务，不递归删除目录。文件被替换时保留；权限、挂载和临时 I/O 故障一小时后自动重试，其他批次继续处理。关闭选项会停止尚未执行的清理。

删除下载目录中的硬链接，不会删除整理目录里的另一个链接；二者共享数据内容，原地改写仍会影响整理副本，因此保留变化检查。未变化文件复用 HASH；仅元数据变化时可能重新核实一次内容，不会每小时重算。

异常页的“删除孤立字幕…”先列出具体本地路径，再由管理员确认。仅允许删除已知清单中的字幕，要求对应媒体缺失、同目录没有媒体且目录可读；目录读取失败不视为空。确认有 10 分钟有效期，确认时重新核对范围，执行时再核对文件身份。删除意图和每个文件结果持久化，失败一小时后继续；完成后终止批次并保留全部记录。

“终止此批次…”需要另行确认，保留本地及云端文件，停止重试与后续异常提醒；保留任务唯一标识，历史扫描不会再次接管同一批次。已经进入 MP 发送队列的通知无法撤回。移动结果未知的批次不允许终止或删除字幕。以上操作不清理云端暂存，也不寻找移走的本地文件。

- **首次启用**：只接收之后的 MP 整理记录，不扫描整个旧媒体库。后续重启或停用再启用，会从已有检查位置恢复。
- **批次范围**：一个下载器任务对应一个批次。自动接收的新批次依据下载器选中的媒体/字幕清单及 MP 成功整理记录核对；MP 保存目录已包含种子顶层目录时，以记录的完整路径确定拼接根，避免重复一层。未选中的文件不加入，已明确关联同一任务的额外字幕整理记录也会加入。显式存量接管则使用上述固定快照。
- **等待齐套**：选中的字幕尚未下载、尚未整理、整理失败，或文件缺失时，整批等待。不会用“目录几分钟没变化”代替完成依据。
- **上传**：完整接管清单先落库，再计算每个整理文件的 SHA1 和前 128 MiB 哈希；不再重复读取下载源。每完成一个 HASH 立即保存，重启不丢弃已有摘要。计算前后核对接受的文件身份与内容变化，防止核对后被替换。后续小时重试复用 HASH，每次上传前后仍检查文件是否变化，内容变更则停止交付。
- **核对**：通过 CD2 强制刷新并递归读取该批次，对照完整文件集合和大小；CD2 返回 SHA1 时也会比对。清单允许在移交前增加文件，已封存文件被移除、替换或大小变化时停止移交。
- **暂存缺失补传**：移动意图尚未发出时，已上传文件连续两轮新鲜目录读取均缺失，且两轮间隔至少一个检查周期（不短于一分钟），才重置该文件的上传完成标记。保留 HASH、秒传次数、下一次尝试时间及上一份回执；同名文件内容不符或目录读取失败时不覆盖、不按缺失处理。移动意图发出后禁止走补传路径。
- **整目录移交**：核对全体文件齐套，同时读取并复核 CD2 返回的 115 云端目录 ID，将 ID 与移动意图一起持久化，再调用一次 `MoveFile`，只传入外层批次目录。设置同名冲突为 `Skip`，禁止跨云盘移动和递归合并。未返回可用云端目录 ID 的接口仍沿用完整清单核对恢复。
- **重启或响应丢失**：保持同一批次 ID。上传回执丢失时，仅在云端文件 SHA1、大小均相符时接续。移动前崩溃时，重新核对完整源目录及其身份后可以继续移动。CD2 成功回执未包含目标路径时，还需确认源目录已消失，防止将同名跳过误判为成功。
- **保留空目录时自动恢复**：移动回执丢失后，如果源目录已消失、待归档位置的目录 ID 与移动前保存的 ID 相同，即可自动恢复为“已移交”。Symedia 已搬走部分或全部文件均不妨碍确认，不会要求文件留在待归档目录，也不重传或重移。开启 Symedia“移动后删除父文件夹”会失去此证据；同名新建目录、ID 缺失或变更不会被误认成原批次。旧批次若没有保存移动前 ID，只有源目录仍完整时才能补录，不能从已经搬空的目标目录倒推。
- **后到文件**：移交前新增的关联附件自动加入当前批次，保留已有 HASH、重试次数和上传回执；所有文件齐套后才移交。移交之后出现新的关联整理记录会通知“后续变更”，不会单独补送字幕或重发视频。
- **重新检查**：修复下载器、文件、目录映射或连接后，在插件详情页点击。它保留原批次及回执，不等于删除旧任务重新发送。
- **归档核对恢复**：移动回执丢失、源目录与待归档目录均已消失时，可在记录中点击“核对归档目录”，浏览并选择归档后的具体作品目录。此动作只保存核对目标，下一轮自动检查所有视频和字幕的 SHA1、大小及份数，允许文件改名。缺少文件或云端不返回 SHA1 时保持异常并重试；不能选择暂存、待归档目录及其上级，也不能越出原 115 挂载。成功后保存逐文件对应路径，显示“归档文件已核实”，提交 MP 通知。它证明完整内容存在，不证明 Symedia 的刮削、Emby 入库等后续逻辑已完成。目录身份与完整文件清单两种证据都不可用时，未知最终目录仍需管理员选择，不能仅凭原目录消失自动确认成功。
- **停用/改配置**：停止发起新操作；已经进入储存提供者的单文件上传可能继续完成。完成后旧工作进程不会发起目录移动；文件锁防止新旧实例同时处理同一队列。进行中的批次不会随目录配置变化而改投别处。

每次调度最多处理 3 个到期批次，每批最多计算 4 个新文件 HASH、尝试 4 个到期文件的上传。已有 HASH 的文件优先尝试上传，新文件完成 HASH 并保存后即可尝试上传，不必等整批全部算完；最终齐套核对和整目录移交条件保持不变。仍只有一个媒体工作者，没有引入文件级公平轮转或并行上传，单个大文件仍可能长时间占用它。秒传未命中和已发出的秒传请求错误保留每文件一小时间隔；账号冷却更长时以冷却为准。其余临时错误按 1、2、4、8、16、30 分钟退避，之后持续自动重试，不再在第 10 次永久停工。整理记录读取失败不阻塞已入队任务；挂载恢复后也能继续。目录冲突、文件内容变化等每小时重新核对，条件未恢复时不冒险执行。

### 为什么待归档目录里仍有批次文件夹

待归档父目录固定，里面每个独立批次目录用于视频与字幕的一次性移交、同名隔离及目录 ID 恢复。Symedia 搬走媒体后，空目录可能保留；它不表示重新上传。复用同一个子目录需要等待上一批完全消费并释放该路径，否则会发生冲突，或必须改成逐文件合并而破坏齐套移交。

本版本不自动删除云端空目录，也不打开 Symedia 的删除选项。CD2 当前删除接口没有“仅为空且目录 ID 相符时删除”的服务端条件，“先查空再递归删”无法保证不误删期间写入的内容。后续空壳回收需先验证安全的非空拒绝能力；对移动结果尚未核实的目录始终保留恢复证据。

默认启用 MP 通知：首次处理异常即通知，持续异常最多每天提醒一次；超过一天未齐套也会通知。详情页显示原因、下次时间和重新检查入口。通知失败不阻塞恢复。单个普通上传的速度和超时仍由 MP 储存提供者管理，不能强行中断其执行。

## 当前支持边界

- 适用于有 MP 下载记录、下载器任务清单和逐文件整理记录的普通影音文件及外置字幕。MP 的自动订阅下载和手动搜索下载均可走这条链路。
- 没有下载任务标识的手工导入、BDMV 整目录原盘，以及无法关联到任务的外来字幕不自动交付。选中但被 MP 排除整理的样片等也会等待，需要先在下载器或 MP 中处理相应文件选择/整理问题。
- 不等待未来可能下载的字幕；只对本次已知清单负责。一个已交付的种子任务之后再选择新集数或更换附件，不会自动形成第二批。未来字幕尚未产生时，任何固定等待窗口都不能证明它不再到达。
- 保留的是本批媒体与字幕相对于整理根目录的目录结构；不镜像整个媒体库，不上传 MP 之后异步刮削产生的 NFO、海报等。元数据文件交给 Symedia 生成。
- 不修改 MP 订阅、PT 站点访问、搜索或 RSS 流控；不修改其他插件的上传队列；不删除下载器源文件和暂存数据；仅在显式开启上述选项后清理已移交的本地硬链接整理副本；不直接通知 Emby。
- 详情页“已移交”仅表示 CD2 确认移动，**不表示 Symedia 已完成归档或 Emby 已入库**。单个目录移动请求及预先齐套核对，仍需在实际 CD2/Symedia 的监听方式下验证可见性和处理结果。
- 页面操作沿用 MP 登录 Bearer 认证，并额外查询当前有效用户的管理员权限。普通用户、停用或已删除账号不能查看处理记录、扫描、接管、重试或选择恢复目录；克隆实例也使用同一权限要求。
- 批次回执位于 MP 插件数据目录下的 `SymediaBatchBridge/batches.sqlite3`。请持久化整个 MP 配置/插件数据目录；回执丢失可能导致无法识别已经处理过的任务。不要为了重试而删除记录。

## 安装与验收状态
