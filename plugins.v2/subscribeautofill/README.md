# 订阅自动填充

## 3.18：回填不能代替选源规则

本插件只监听 `DownloadAdded`，即**下载已经添加后**，再回填已有的电视剧订阅。
它不在下载前选择资源，不开始、暂停或删除任何下载，也不会修改全局规则、分类策略或订阅的 `filter_groups`。
因此，回填页面后来显示 1080p，不能单独证明插件导致第一次下载了 1080p。

### 推荐设置

开启“尊重优先级规则”，填充内容选择“制作组”和“站点”。规则保护默认开启，升级旧配置时缺少该选项也按开启处理。

存在规则组时，插件按下面的顺序获取规则：

1. 单条订阅的 `filter_groups` 非空时，使用这条订阅自己的选择。
2. 否则，普通订阅使用 `SubscribeFilterRuleGroups`；洗版订阅使用 `BestVersionFilterRuleGroups`。
3. 确认组名仍存在，媒体分类有适用组，再使用 MoviePilot 原生 `filter_torrents` 对已下载资源的副本复检。
4. 名称失效、仅前置组适用而没有选中的分类组适用、规则为空、缺少上下文、候选不通过或复检异常时，**跳过全部回填并写日志**；不会将失败当成允许。

规则存在且复检通过时，分辨率、资源质量、视觉特效、音频特效、视频源仍由规则负责。
即使旧插件配置选中了这些填充选项，也不会把本次资源的 1080p、WEB-DL、DDP5.1 Atmos 等写成新的硬条件。
只填用户选中的制作组/站点，且不覆盖已存在的 include、effect、站点等字段。

例：全局规则要求4K，但手动或其他路径下载了1080p。插件在下载后复检时发现不通过，**不据此将订阅锁为1080p**。
但已添加的下载仍然存在；首次选源问题需检查 MoviePilot 或实际触发下载的插件链路。

### 保留的锁版模式

明确关闭保护，或确实没有配置任何优先级规则组时，继续按“填充内容”生成硬条件。
此时 DDP5.1 Atmos、平台等不是加分，会排除不符合条件的其他版本；覆盖模式仍会覆盖 include 并清空 effect。
这是兼容旧用途的可选行为，不适合希望规则自主升级来源/音轨的订阅。

### 源和组名识别

- 每条视频源正则的所有分支都有 ASCII 词界，`CR|Crunchyroll` 不再匹配 `Crew` 中的 `Cr`。
- 使用长度最长的有效匹配，保留 HBO Max 优先于 HBO；正则候选为空或非法时跳过。
- 生成的来源/组名条件也带边界；MWeb 不匹配 AilMWeb、MWebExtra。
- 支持 `DDP5.1 Atmos` / `DDP 5.1.Atmos` 等字面连接符变化；不把 5.1 擅自等价于 7.1。
- 组名保留 `-AnimS@ADWeb` 的组合标记。没有新增官组白名单。
- 站点只在启用、且属于全局订阅站点范围的站点中选择；已有单条站点选择不改。

### 状态和升级

处理记录按“订阅ID、媒体ID、季”隔离。旧的剧集级记录保留，但不再阻止其他季回填。
不明确的多季下载不再被套用到全部季的订阅。插件回调串行化，更新历史记录保留回填前字段。

**升级不会自动清理之前回填的条件。**历史上的1080p、WEB-DL或包含正则，可能混有用户手动设置，不能可靠自动区分。
请在受影响的订阅中人工确认并移除不再需要的音频/来源锁定，按实际需求设置分辨率、规则组。
“清理历史记录”和“清理已处理记录”都不会修改订阅字段。

日志新增“下载后规则复检”，包含订阅ID、普通/洗版/单条来源、分类、适用组和结果。
这些日志只能证明回填时的复检结果，不能补写或证明下载前实际使用的规则。

## 开发与测试

仓库根目录执行：

```bash
python -m unittest discover -s tests -v
python -m py_compile plugins.v2/subscribeautofill/__init__.py
```

测试运行真实的插件匹配函数和事件处理函数，MoviePilot数据库、事件上下文与原生过滤调用以fake提供。
没有连接真实 MoviePilot、Rust 扩展或下载器，因此不是实机/下载前全链路验收。

本次只修改本插件、其清单版本以及回归测试；不修改其他插件的策略。
