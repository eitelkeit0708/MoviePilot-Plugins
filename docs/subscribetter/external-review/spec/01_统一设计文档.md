本设计合并本次长对话、此前v0.1/v0.2需求稿、2026-09-14规则修订材料，以及其后的明确决定。**后续用户决定优先于旧稿；旧文件仅作追溯，不与本稿同时充当冲突的产品规范。**

### 0.1 v1.1 修订范围与效力

本版在v1.0上合入此后用户已认可的**丢事件恢复、候选观察、下载进程感知、等待秒传期间计划取代、发布前复核、升级冷却和分级清理**。这些规则直接修改主流程，不是额外安装的智能订阅插件，也不拆成以后再做的阶段。

- “全程占用”改为“同一目标只有一个有效交付权，交付前可受控转交，交付中及结果不明时不得越过旧操作”。旧计划永久持锁等待秒传不是正确实现。
- “秒传成功”只代表传输结果。计划已被取代时，即使旧请求一天后成功，也不能进入Symedia消费目录。
- “实时监控”仅降低延迟。持久化任务、主动查询和覆盖全范围的周期对账是正确性基础；不依赖inotify、Webhook或MP广播事件必达。
- 下载器数据删除开关默认关闭。监控目录的成功清理与明确放弃清理分别配置；后者不要求先上传成功。
- 现有分类准入、词典序质量偏好、同质量特效例外、两段路径与CD2样本保持不变。本文“高/低版本”按插件独立策略比较，不恢复原生分数权威。

以上是v1.1已经确认并继续保留的业务合同。本版增加V3开发边界与两个插件/解析对话的整合；完整差异见《05_v1.2_变更说明》。新增与既有运行合同仍须由Codex按V3实机能力验证。

## 1. 产品目标与责任边界

### 1.1 统一目标

针对授权范围内的作品/季/集，持续回答四个问题：**现在有哪些版本；本轮应当补齐/替换什么；计划是否真正交付；何时停止主动处理并等待新机会。**

统一处理下列场景：首次下载、连载逐集补齐与升级、已完结混合质量剧集、电影升级、手动排除与自动换源、到期被动监控及一次性唤醒、旧库无下载历史建档、规则调整后重新比较，以及发布规格陆续到达、秒传长期等待、旧计划迟到成功和漏事件恢复。目标是在不放宽准入、不降低在库质量的前提下减少重复下载和过期交付；不承诺能预测未来最佳版本。

### 1.2 分工

| 组件 | 负责 | 不让其额外负责 |
|---|---|---|
| 内置榜单发现及其他入口 | 复用DoubanRankPlusOptimized榜单/自定义RSS能力，向统一入口提交收录意图 | 不直接绕过调度创建原生普通订阅，不与旧榜单插件双跑。 |
| MP站点/识别/下载基础 | 站点认证与解析、媒体元数据、种子读取、已配置下载器客户端、下载与整理基础及记录 | 不让其原生质量规则与100分再决定受管任务。 |
| 本插件 | 独立策略、候选池、逐文件计划、在途状态、排除、期限、归档RSS、115交付与文件来源关联 | 不写BT协议，不接管所有其他插件，不取得无关目录删除权。 |
| MP既有本地整理 | 将下载后的内容按用户选择的移动/复制/链接方式放入监控目录 | 本插件不重命名一次又让Symedia再重命名一次。 |
| Symedia | 继续按现有配置进行最终整理/替换、STRM生成与更新 | 不要求新增pickcode、不强行改HTTP STRM、不复制另一套质量权重。 |
| CD2 | cloudfs挂载、普通上传任务、元数据查询/刷新 | 队列消失或缓存可见不等于115远端已核验。 |
| Emby | 当前媒体身份、季集、具体MediaSource与媒体流 | GET读取不是强制重新ffprobe，不把条目存在当完整播放验证。 |

接管增强助手的**洗版相关职责**，包括模式、在途/完成保护、相关期限与排除协作。通用待定、暂停、站点元数据辅助和其他功能不整体重写；若它们仍会改写受管任务，须按功能隔离或适配。名称AI由内置ChatGPTPlusUltra功能模块提供；确定性Meta纠错与AI提取职责分离。旧识别组件在明确迁移切换后停止重复响应，非重叠插件功能不一刀切关闭。

### 1.3 单一管理者

对每个受管目标只有一个决策者。本插件出错不能悄悄回退到另一套原生规则自动下载。未受管订阅、普通手工搜索的质量决策和无关目录保持原样。**显式启用宿主级Meta热补丁是唯一例外**：经公共Meta入口的未受管解析也可能得到纠正；不得把它宣传为只影响受管订阅。

同一作品可能有不同季或不同剧集组目标，不能仅凭标题合并管理权。显式用户停止、解除纳管、返回原生控制和“因到期暂不主动搜索”必须区分。

## 2. 核心对象与不变量

下列名称为**拟实现的插件内部对象**，不是声称MP已有同名接口。

| 对象 | 作用 |
|---|---|
| `MediaIdentity` | 媒体类型＋V3 `media_source`＋字符串 `media_id`；可信跨源身份映射另存，不比较裸ID。 |
| `TargetUnit` | 电影，或特定season/episode/episode_group；无季集电影不得伪造S00E00。 |
| `MediaVersion` | 某内容版本及其视频、字幕、附件资产；可同时存在多版本。 |
| `FileContent` | 每一物理文件的完整SHA1＋字节数；不是种子infohash。 |
| `FileLocation` | 本地、115、CD2、STRM、Emby定位及其有效时间；相同内容可有多个位置。 |
| `Candidate` | 站点发布资源、原始描述和身份依据，可信识别与目标信息回填分开。 |
| `ManagedTask` | 持续任务/一次性任务、用户范围、策略快照、期限、归属及运行状态。 |
| `ExecutionPlan` | 某次决定使用哪个资源、下载哪些具体文件、改善哪些目标及理由。 |
| `DeliveryBundle` | 本次已准备好的视频与明确绑定配套文件组成的交付单元，不是永远增长的整部剧目录。 |
| `Exclusion` | 资源/目标/内容层面的精确排除或冷却记录。 |
| `OutboxAction` | 上传核验后待刷新、待交付、待归档等可恢复外部操作，绑定计划及其目标代次。 |
| `DiscoverySource / DiscoveryRecord` | 榜单来源、RSS项、收录条件、识别/处理状态、重试及目标关联，不与PT资源候选混为一表。 |
| `SubmissionIntent` | 所有发现/手工/旧订阅入口共用的幂等收录意图；提交回执关联ManagedTask及可选原生委托壳，不直接触发下载。 |
| `ParseCorrection / ParseRevision` | 原生与纠错差异、规则版本、显式约束、路径上下文及覆盖范围，保留原文可重放。 |
| `AiRequest / AiRuntime` | 原文约束名称提取、缓存键、调用合并、额度/错误统计及配置代次，不携带下载执行权。 |
| `MigrationReceipt` | 旧插件配置/历史版本、脱敏校验和、映射结果、部分失败及切换状态，不代表旧任务真实完成。 |
| `TargetSchedule` | 每目标的候选观察起点/截止、当前首选、升级冷却、切换预算；跨RSS与重启保留。 |
| `PlanAuthority` | 每目标当前有效plan、generation及交付阶段；与旧计划仍在收尾的外部操作分开。 |
| `PublishAttempt` | 一个交付动作的已登记意图、覆盖目标与代次快照、远端结果及是否仍可能迟到。 |
| `ReconcileCheckpoint` | 本地/云端/Emby各自的对账范围、游标、完成水位、失败和下次执行时间。 |

**必须保持的不变量：**

- 物理存在、质量属性、来源证据、在途目标相互独立，不用一个分数代替四种事实。
- 同一目标同一时刻只有一个有效交付权；未交付计划可经事务转交。失效计划可保留收尾记录，但不得继续下载决策、秒传重试、创建普通上传或发布。相同文件内容可以复用，目标对象归属仍须明确。
- 交付前可取代不等于任何时刻可强行解锁；进入PUBLISHING或交付结果不明，必须先核实旧动作不再可能迟到覆盖。
- 下载任务提交前持久化目标占用，不等DownloadAdded/hash回调；整包、单集、双集资产共享实际覆盖范围的冲突检查。
- 通知为提示而非事实，文件仍可查询且服务与消费者恢复能力具备时，漏事件可由对账收敛。对瞬时出现又消失的对象和没有补处理入口的消费者不作无条件恢复承诺。
- 计划内具体文件范围在提交前确定；空范围绝不解释为“下载全种”。
- 已投递任务不等于已下载，下载完成不等于远端交付，远端交付不等于Emby当前版本已核验。
- 任何删除只针对登记过、仍是同一对象、位于授权范围内的文件；正式媒体库不隐含授权删除。
- 暂存成果未齐套不能发布，CD2刷新失败不重传已成功文件。
- 原生分数不再是插件的权威事实；不得通过伪造分数来绕过完成/升级条件。
- 对话中实测SHA1样本只作为接口及路径样本，不作为所有媒体已核验的证明。

## 3. 总体结构

```text
内置榜单/自定义RSS/原生新增/插件操作/选定Emby媒体库
                     │
           任务归属与配置快照
                     │
MP站点搜索/RSS原语 → 独立候选池 ← 精确排除与失败记录
                     │
      确定性Meta纠错 → 身份/范围核验
                  ↑
       按需AI名称辅助（不在Meta热路径）
                     │
        独立准入 + 分类排序 + 升级比较
                     │              ↑
         观察/冷却/进程感知与计划调度   当前版本档案
                     │              ↑
               ExecutionPlan     有效交付权/代次
                     │              ↑
      MP配置客户端 + 严格文件索引执行
                     │
               MP既有本地整理
                     │
          监控目录 → 冻结文件清单
                     │
      115隔离暂存：秒传/受限CD2普通上传
                     │
           完整资产组远端核验
                     │
           有效计划/当前质量再核验
                     │
        串行目录交付 + CD2刷新持久化待办
              ┌──────┴────────┐
      清理获授权本地文件      Symedia整理/覆盖/STRM
                                  │
                        Emby → 两段路径映射 → CD2
                                  │
                      Hash/大小/身份/媒体流对账
                                  │
                     当前版本更新/升级冷却/完成本轮
```

全过程由数据库待办与本地/云端/Emby主动对账驱动。inotify、MP事件、Emby通知只触发提前检查；Symedia漏事件后的补处理需要单独验证已有入口。

代码建议按职责组织为`discovery、meta_corrector、ai_assist、ownership、policy、candidates、planner/scheduler、mp_adapter、archive、delivery、reconcile、lifecycle、exclusions、ui、db`模块。不是多个独立插件；共用数据库、目标键、策略版本、任务/计划和日志。组件之间通过明确返回类型和持久化事件协同，不靠读取彼此的日志推断成功。

## 4. 原生订阅接入与隔离

### 4.1 入口与受管范围

配置“自动纳管新订阅”的媒体范围与必要过滤条件；独立配置“旧库RSS监控”的Emby服务/库ID。两者不是同一个开关。手工纳管可按作品/季选择。

新剧集从建立受管目标时即支持逐集补缺与升级。这是插件业务语义，不要求原生`best_version=1`始终承担决策。用户显式指定只补齐、不升级或锁定模式时保存其选择，不能自动放宽。

### 4.2 原生记录是配置壳，不是运行状态真值

读取并快照原生媒体身份、季集范围、episode_group、关键词、用户、站点、下载器、保存目录及自定义识别词。原生旧质量条件只作迁移输入，转换为本插件策略后显示“由插件策略接管”，不得继续偷偷生效。

已认领记录通过V3公开订阅入口置为暂停委托壳（基线状态码S须在实际版本核验），插件页面显示“已委托/插件活动”，与用户停止区别。V2显式sid可绕过S是历史风险输入，V3手动/定时路径必须重新验证；任何版本均不能仅靠状态字段代替执行守卫。[V3DOC01；历史MP04]

- `ResourceSelection`：对原生来源的受管候选拒绝/移交调度，不在同步回调中执行慢上传或递归搜索。
- `ResourceDownload`：最终确认是否持有本插件已登记的有效计划；拒绝受管原生重复提交。
- `SubscribeCompletionCheck`：非插件已授权关闭动作默认否决；自己的完成不依赖100分。
- 受管计划使用专用origin和不可被普通文本匹配冒充的计划上下文校验。origin便于追踪，不是安全令牌；实际以库中计划和调用上下文为准。
- 纳管判定须涵盖符合自动纳管条件的新记录，不能等SubscribeAdded异步回调写入后才开始保护。已在进行的原生任务先做领养/等待/冲突提示，不重复下载。

宿主check可能继续更新原生壳元数据；插件接受可信元数据变化，但不把宿主派生分数当运行状态。总集数缩减、剧集组调整、服务库移动需要重新核验，不因一个临时结果大范围删除目标。

### 4.3 结束、暂停与退出插件

插件任务历史先持久化为权威记录。原生壳归档使用受控适配，保存历史配置并删除/归档壳的步骤须可重试、可区分用户删除与插件完成；避免SubscribeComplete又触发旧助手新建任务。无可靠归档入口时可暂保留已停止的委托壳并报告，不伪造100或抹掉事实。

用户在插件页面暂停/停止后，相关计划不得继续准入。原生显式删除记录需同步为用户停止，除非是已登记的插件归档操作。归档后由选择库被动监控的任务保留；明确停止优先于库级默认。

插件停用、升级异常或失去关键接口时，现有委托壳保持暂停，提示明确返回原生控制；不恢复一堆未经校准的旧规则。恢复原生前展示配置快照差异。未受管质量/执行行为不变化；启停明确授权的全局Meta包装会改变其覆盖范围内的解析，需单独说明。

### 4.6 V3媒体身份、分类和运行环境

## 5. 候选获取与身份确认

### 5.1 不经过原生质量条件的入口

首选`ChainBase.search_torrents/async_search_torrents`配合宿主Indexer和服务配置；可复用`TorrentsChain.browse/rss`获取新发布。鉴权、站点解析、流控、代理仍属MP能力。这里沿用已确认的职责边界，具体公开签名与分页行为必须用V3核实；历史MP02、MP03、MP08不单独构成V3兼容证明。[V3DOC01]

高层`SearchChain.process(rule_groups=[], filter_params={})`可作为经验证适配，但必须处理其标题描述去重、借用目标MediaInfo和搜索词提前终止等局限。不得调用默认标题搜索API后误以为拿到了未过滤候选。`[]`/`None`差异及candidate_filter阶段在V3重测；原生早期Meta过滤风险已在用户提供的V3对话中定位，不把结果过滤器当原始候选入口。[CONV01；历史MP01]

站点列表为空的语义由本插件明确：未配置授权站点则不抓取，不让宿主的空列表回退成“全部站点”。遵守授权范围及已有流控，不因某站失效自动扩大到未授权站。

### 5.2 搜索词与识别词分开

复用用户自定义识别词但不把中文名和英文名机械拼成一个搜索词。优先当前可信名称，再按站点语言能力使用原名/别名；第一个词只返回无关/不合格结果时，可以继续有界尝试其他名称。设置最大站点并发、关键词数、分页数、间隔，实际命中/未命中分别记录。

数字属于作品名时保留，不能统一正则删数字。明确媒体ID冲突不准用同名兜底。`match_source=title`或`media_info_is_target=True`不是候选自证身份；严禁把目标ID赋给未知候选后说“ID已核验”。

### 5.3 候选身份与存档

主键优先`site_id + torrent_id`；可补充已解析infohash和规范化详情页路径。标题、大小仅作候选定位和诊断，不作唯一身份。敏感下载链接、passkey和cookie仅在内存/宿主凭据中使用，持久化引用或脱敏字段；日志不可输出原链接。

同标题/描述的不同种子不能在策略评估前错误去重。同infohash跨站是否共用失败记录取决于原因：下载链接404是站点项问题，内容不符合是内容问题，115暂时无秒传是时效交付问题。

纯RSS没有副标题/标签时，必要条件可调用宿主现有详情/搜索能力补齐；取不到则延期/报告数据不足，不当成没有特效字幕或强行放行。整个候选过程不下载视频以试探质量，不承诺未知候选已有完整文件SHA1。

### 5.4 确定性Meta结果纠错与唯一热补丁例外

整合用户上传对话最后的简化方案：**原生解析 → 有证据的局部纠错 → 返回兼容Meta对象**。不是从头重写解析器，不在Meta热路径做网络、LLM、远端数据库查询或逐文件ffprobe。普通title、subtitle、规格字段和所有原文保留，纠错记录与视频质量排序分离。[CONV01]

首选让受管候选调用共享`MetaCorrector`；另提供显式的“增强宿主公共解析”开关，在启动时安装一次窄包装，使原生搜索/RSS/整理/测试调用也能在过早过滤之前得到修正。受管流程显式调用与宿主包装使用同一纠错核心和revision，处理幂等，不套两份规则。关闭全局包装时，受管流程仍可调用自己的纠错；未受管主流程不声称已得到覆盖。

V3.0.4核实的两个候选适配点为：

| 内部函数 | 可用输入与边界 |
|---|---|
| `_build_python_meta_info(title, subtitle, custom_words)` | 原生Python完成显式标签处理和original_name生成后返回；可获得本次输入与自定义词上下文。 |
| `_meta_from_rust(parsed)` | 只有Rust结果字典，没有原函数的custom_words参数；不能假设可恢复被省略的原始上下文与显式锁。 |

`MetaInfo/MetaInfoPath`内部动态引用以上函数；只给外层MetaInfo重新赋值不能可靠替换已导入的函数引用。公共路径解析的Python分支在构造文件/父目录后仍会merge，两个补丁点不能无测试地宣称覆盖了最终父目录合并。直接构造MetaVideo的外部代码也可能绕过这些点；覆盖报告必须列清楚。[V3META01]

纠错范围：数字片名保护（含GATE24/CODE46等回归）、括号块角色判别、明确季集及范围、电影/剧场版/电视剧形态冲突、主副标题证据合并。只在有可靠文本/明确用户规则支持时更改；不机械把尾数当季集，不把全部裸数字规则删除。名称修复须同步清理或重算错误type、begin/end及total字段；S00的0与None区别保留。对未受影响的分辨率、编码、HDR、制作组和音轨字段保持原值。

用户显式识别词/身份标签/季集偏移优先。优先级应为：明确用户约束 → 候选自身明确证据 → 有边界的通用推断。只因订阅正在找某作品，不得把全部候选注入该作品ID。Python/Rust修正保持共同语义；Rust输出无法证明显式约束来源时，保守跳过可能冲突的字段修复并留原因，不凭空重建、强制关闭Rust或重跑两遍全解析器。

补丁生命周期最低合同：在单独`compat/metainfo_patch`内维护固定版本/签名白名单，保存原函数和所有权；启用/保存/重载不叠包装；在副本上纠错，失败返回未损坏原结果；撤销时仅在当前引用仍属于自己时恢复，若第三方后包裹则停用自身逻辑并报告冲突，不能覆盖别人。此处允许内部模块引用只是明确的兼容债务，**不是官方稳定SDK**；禁止推广为修改任何函数的通用补丁系统。

原生fallback并不授权受管调度忽略身份矛盾：已知高风险且纠错不可用时，受管候选仍应DEFER/ERROR，不靠原生“非空”强行下载。音乐、音频文件以及影视外挂音轨的force_video等分支均需要不回归测试，不扩展音乐订阅功能。

### 5.5 内置AI名称辅助：迁移ChatGPTPlusUltra而非再加一个响应者

保留1.4.2的功能约定：严格两个字符串字段`name/year`，未知年份为空字符串；以输入原文为证据，不联网补片名、不猜provider ID、type、season/episode或技术规格。模型不输出置信度来代替证据。保留括号内可信片名优先、独立别名标记边界、续作/剧场版保护、制作组拒绝以及结构/重复键校验。[UAI01、UAI02、UAI03]

确定性解析清晰时不必调用AI；无法确定名称或出现可解释的身份冲突时才进入有界辅助。不能把“原生非空”当永不检查的理由，也不能把全部候选先送LLM。LLM调用位于独立识别服务，不位于两个同步热补丁中。其输出与纠正后的Meta结合，再由V3媒体来源查询确认身份；AI接受、候选提交、最终媒体匹配、下载和入库统计分开。

复用OpenAI兼容API基址、keys、模型、请求profile、代理、timeout、重试、并发上限、正/负TTL与容量、完整提示词迁移备份、日志脱敏和真实Token统计。1.4.2默认模型deepseek-flash只记录为旧配置默认，不在设计中替用户改模型或保证供应商当前协议。复用传输算法时核验其HTTP库与V3共享环境，不引入全局网络猴补丁。

缓存保留完整输入语义：title、实际送入的subtitle/上下文、endpoint/model、有效提示词、校验协议、相关解析revision参与键；同请求并发合并，正/负结果分开；不剥画质和电影标记构造激进跨质量身份缓存。来源代码原缓存为实例内存，不宣称能原样迁移其内容；调度重试/冷却等必要恢复状态独立持久化，避免重启重置预算。401仅按明确鉴权错误有限换key；429/Retry-After、网络、配置、结构拒绝分开，不用换key绕过服务商限流。[UAI01、UAI02]

默认内置名称提供者是唯一AI调用者；`NameRecognize`仅作可选宿主桥接并按V3真实合同处理，不假定加字段便能替换完整Meta。内部调度不依赖“优先使用插件识别”开关；不能因整合自动打开它并使全站点每次识别都调用模型。已有AIRecognizerEnhancer等响应者需冲突检测/明确切换；不得自动重写无关插件设置。

源插件有独立普通聊天功能，**保留为可选消息模块**，新安装默认关闭，迁移展示旧开关与路由后由用户确认；保留按渠道/用户隔离、限长历史与清除会话能力。聊天不是Agent控制面，不允许模型回复直接订阅、下载、改规则或删文件，也不得同时触发两个聊天回复者。是否接入V3原生聊天能力需按等价行为验收，不能借整合悄悄删掉这项已有功能。[UAI02]

### 5.6 内置榜单发现：迁移DoubanRankPlusOptimized

保留1.0.7源码已提供的可观察能力：内置榜单选择、自定义多行RSS、cron/运行一次、代理、电影限定、年份下限、评分阈值、全季度订阅选择、来源类型提示、来源保存目录、历史/统计/未识别记录清理以及配置/历史迁移。旧配置中的访问间隔及限流选项需迁移并验证实际生效，不能把留存配置或注释当已经执行的功能。[URANK01–URANK04]

保留旧RSS `URL@@TV/MOVIE` 和分号/`#`路径、`@tv@/@movies@`语法作为**导入适配**，转成结构化source配置后运行；新界面不要求用户维护多种分隔符组合。全部旧榜单选项和可取得的地址从固定源码/实机配置导入并逐项报告，不临时换RSS源。固定源码UI列出8种榜单，但本文件引用的`_douban_address`未见定义；因此选项存在不证明内置地址可用，缺少地址应显示待配置/待核对，而不是猜一个RSS服务。榜单RSS是“作品发现”，PT RSS是“可下载资源发现”，二者分别命名、存储与统计。

每条发现记录先获得可审计身份与收录判定，再向统一`SubmissionIntent`/目标入口提交，不直接调用旧式`SubscribeChain.add(...best_version=0)`。榜单不产生另一套下载队列、原生分数或生命周期。用户显式STOPPED/排除/解除纳管优先；多榜单、反复RSS和手动入口对同一可信媒体/季只建立一个管理目标。

“订阅剧集全季度”意为是否考虑多个季，**不是完结后转整季包、不是best_version_full**；逐季检查真实元数据和现有范围，不凭number_of_seasons构造不存在的季，默认不把S00当正片季。只有部分季缺失时只创建对应目标；同作品多个季度记录状态须逐季归集。新增目标按既定逐集补齐/升级与观察期运行。

源代码评分实际读取识别结果`mediainfo.vote_average`，不一定是豆瓣评分。迁移将阈值与评分来源一并记录；不能把原来源阈值悄悄改为豆瓣阈值。未知年份/评分与明确低于阈值分开处理；按有界重试和策略版本重新判断，不能一旦“未识别/评分不够”就永远当已处理成功。

源代码`__clean_title`在TV提示下把末尾2–9转换为季号，与数字片名保护存在冲突。迁移后它仅可作为有额外证据、限定来源或用户精确规则的别名候选，不作为普遍字符串重写；`@@TV`只能证明用户希望查TV，不证明末位数字一定代表季。共享MetaCorrector统一处理，而不是榜单先破坏名称、AI再猜回来。[URANK03]

媒体库已存在不能等价为所有事情完成：发现记录链接当前档案；符合既有授权被动库范围的对象可继续监控；未授权的旧库不能因一次上榜自动扩大洗版范围。对“已存在只记录/按来源配置纳管”的意图提供明确配置并迁移旧行为，不把旧MEDIA_EXISTS直接变成强制重下。

提交成功必须取得实际目标/宿主壳的明确回执后才记成功。旧源码忽略add返回值、标题/年份/豆瓣ID组合去重、按条目整体历史阻止重试，均仅作历史行为，不复刻为新系统正确性条件。历史清理只删展示/迁移日志，不删除STOPPED、资源排除、业务幂等回执或正在执行的任务；显式重新处理应单独操作。失败、限流、暂时未识别、已存在、已管理、已收录和最终入库分开统计；单来源失败不吞掉其他来源进度。[URANK02]

### 5.7 共享重解析、诊断与旧缓存边界

持久化原始发现项/候选title、subtitle、原生解析快照、纠错差异及parser revision；只对受影响且允许处理的记录进行版本化重解析。宿主热补丁只影响后续调用，不会自动修好已有RSS错误身份；插件自己的候选可安全重放，宿主缓存只在有明确公开能力和授权时定向失效，否则报告范围限制，不清空全部历史或下载数据。[CONV01、V3META01]

重解析不触发取消旧发布、不自动重传、不重置观察/冷却/取代预算；只有新的确定性计划才能执行副作用。策略错误与解析错误分域，解释“未抓到、解析被纠正、身份未确定、准入拒绝、观察中、已取代”各环节。保留正反真实样例，新增找回数量不能掩盖错片/错集回归。旧源码报告的130个离线测试只作迁移输入，须在V3新模块重新运行并报告未覆盖部分。

## 6. 独立策略系统

### 6.1 三层分离

1. **准入**：明确媒体身份/范围、可接受分辨率、语言、来源、发布组、禁止形式、排除表和显式锁定。
2. **排序**：分类定义的按顺序比较。第一个有差异的有效维度决定优劣；后面的优势不得抵消前面的劣势。
3. **等待与升级**：缺失时选择当前合格候选，按明确配置的观察期决定何时执行；已有时只改善或执行授权例外，并受本目标升级冷却约束；在途时按第7节受控调度，不把偏好当拒收，也不把CD当作整条订阅暂停。

原配置引用的内置规则（如CNSUB/WEBDL）在迁移时解析为本插件自有谓词，并保留实机自定义覆盖；不得留下运行时调用宿主规则器的隐式依赖。可在测试中用固定旧规则作对照，不把该对照引擎带入正式决策。

策略输入为标准化属性和证据，输出`ALLOW / REJECT / DEFER / ERROR`、可处理目标范围、比较理由、规则版本。`ERROR`不是一种质量档位，`DEFER`不是缺集。规则编写采用结构化`all/any/not`、比较、集合、受限正则及已注册判定器；不开放任意eval、Shell或无界网络代码。

### 6.2 初始分类偏好

以下是用户既有配置的独立表达，不再运行原生规则串。原盘、语言、名单的具体识别从`输入参考`及实机导出迁移，不能丢失前置条件。

| 分类 | 收录边界 | 排序顺序 |
|---|---|---|
| 华语电影、外语电影 | 仅4K，不新增官组硬限制 | 画面→特效中字→REMUX→非REMUX高码→音频 |
| 动画电影 | 4K优于1080p/i | 分辨率→4K画面→特效中字→来源→4K非REMUX高码→音频 |
| 国产剧 | 仅4K、官组、WEB | 画面→高码→音频 |
| 欧美剧 | 4K优于1080p/i、既有官组 | 分辨率→4K画面→特效中字→来源→4K非REMUX高码→音频 |
| 日韩剧、港台剧 | 4K优于1080p/i、既有官组 | 分辨率→4K画面→来源→4K非REMUX高码→音频 |
| 纪录片 | 4K优于1080p/i、不新增官组限制 | 同日韩/港台排序，无特效字幕加分；纪录电影仍按电影路由 |
| 国漫 | 仅4K、官组 | 画面→音频，不新增来源级别 |
| 日番 | 既有平台/组梯队，VCB/B-Global例外 | VCB1080→B-Global4K→主流平台官组1080→B-Global1080→其他官组1080；每梯队内音频 |
| 欧美漫 | 官组1080p/i | 音频 |
| 综艺 | 仅HHWEB | 4K→1080p/i，不额外强加音频/字幕 |
| 现场 | 4K优于1080p/i、不限官组与WEB | 4K画面→音频→高码；1080只比音频 |

共同约束：

- 4K画面DV＞HDR/HLG＞普通或未注明；EDR不单独排序、不自动视为HDR或HQ。
- 1080p与1080i同级，不比较DV/HDR/HQ，也不因含这些标记拒绝；无720p兜底。
- 来源REMUX优于WEB/普通蓝光压制；后两者同级。保留原盘/ISO/BDMV排除，不拿UHD字样直接证明原盘或REMUX。
- WEB-DL与WEBRip同档，按已确认补丁处理技术段裸WEB；制作组CHDWEB和标题里的Web不作来源命中。
- 音频：TrueHD/DTS-HD MA/FLAC＞明确Atmos/DTS:X等空间音频（未命中无损）＞DDP/DD+/EAC3＞其他/未注明。无损内部不再分是否Atmos；PCM/LPCM不加无损档分但不拒收；不加声道数、多轨组合或帧率优势。
- HQ仅认发布标记，不凭码率/体积推断。保留音轨列表供档案，但评分归为上述单一最高已知类别，不制造候选来源无法表示的组合优势。
- 特效中字不跨越分辨率/画面排序，只对明确开启此维度的分类生效。
- 中文可理解性、国语/粤语规则、名单、格式黑名单及其否定表达必须从原配置迁移；不是用“中文字幕存在”一句话抹掉原有边界。
- 分类路由使用V3已发布分类策略及稳定category_id绑定质量策略，保存revision/路径快照，并核验国家/地区覆盖；未匹配类别不能流入无条件通道。对加拿大等遗漏例子保留回归，不编造新的分类名单。

**分类名称不等于国家白名单。**附带category.yaml是旧迁移快照，其中“欧美剧”是其余电视剧的明确兜底，“欧美漫”是国漫/日番以外的动画兜底，“日韩剧”也包含该配置列出的其他地区；在V3分类迁移核对中保留该快照的路由顺序和范围；迁移完成后以V3当前发布策略为准，不在运行时继续读写旧YAML。明确兜底应进入相应严格质量策略，不能把它误当无条件放行，也不能因为名称叫“欧美”就另编国家表。只有没有可用路由/策略引用时才报配置错误。

整季一致性锁（分辨率/来源/平台/画面/组/音频）可作为显式可选约束，优先尊重用户锁。初始未锁就不自动全部锁死，锁与“同一季只能取一档质量”不是同义。

### 6.3 属性证据与已有版本评分

现有版本采集顺序：Emby可稳定提供的技术信息；已确认ffprobe能力缺口由当前文件名/可关联发布描述补足；发布语义如REMUX、组名、HQ用文件名与关联记录。元信息Title中的Atmos等是声明证据，不称为独立码流鉴定。

**候选准入与旧库质量画像分开。**旧库没有制作组字段不代表文件不存在，也不必因此无法比较已确定的分辨率/音频；但对日番等制作组本身决定排序的位置，不能凭空补组名或暗降至最低。需补采/关联，否则对受该字段影响的替换返回明确的数据处理问题。已知信息足以决定前置维度优劣时可给出有据结论，不能把后续未知自动当作已满足硬条件。

多版本只比较仍有效、目标关联可靠且可比的版本。正常缺字段在规则中已有“未注明”语义时按该语义处理；接口出错、规则引用失效与字段正常未注明不可混淆。

### 6.4 同质量的特效声明升级

质量字段仍只有`special_zh_subtitles=true/false`；另存`evidence=explicit/inferred_pgs/...`。

- 当前中文PGS、无明确记录时按用户惯例推定特效。
- 普通ASS/字体数量不自动证明特效。
- PT标题/副标题或字幕流描述明确特效且中文可证实时，记录explicit候选声明。
- 候选与当前版本其他比较维度等价，旧版仅PGS推定、新版explicit且符合准入，允许一次`EVIDENCE_UPGRADE`。
- 不给PGS推定新增质量第三档，不伪造宿主101或永久降低当前评分。
- 声明先绑定候选文件；上传、交付、最终播放来源关联成功后才确认当前版本explicit。
- 同一旧版本与策略语义下，成功后不再反复洗；失败重试沿用同一目标，不因站点重复或规则重排重置。
- 若能证明当前视频及必要外挂资产已与该explicit发布完全相同，直接补证据，不重复传输。

### 6.5 策略版本与预演

保存标准化事实、原始快照、策略内容哈希、解释结果；排序键是派生缓存，不是永久画质数字。改策略时重新比较档案，展示变更和拟动作，不能用旧序位直接与新候选排序键混算。

预演应显示将新增哪些下载/哪些集、为什么不替换、当前冲突/缺证据、会生成多少交付任务。运行时不需要导入原生规则；保留原生策略导出只是迁移和回退资料。

**数据真实性边界：**候选阶段仍按用户已接受的PT声明信任策略工作，不能把一条整包标题说成已经探测过包内每一集。整包不下降判断基于当前已确认画像和候选可信声明；它不是对错误发布标签的绝对保证。发现实际技术信息矛盾时记录异常并重算，必要时可对特定任务补采；默认不引入对整库远端视频的重复探测。

## 7. 逐集与整包计划及统一调度

### 7.1 目标范围与计划生成

计划生成前先读取当前有效版本及在途目标。对每候选计算能够处理的TargetUnit集合，明确区分`ACQUIRE`（确认缺失）、`QUALITY_UPGRADE`、`EVIDENCE_UPGRADE`、`REPLACE_INVALID`和`SIDECAR_SUPPLEMENT`。

- 分集模式：只选有价值目标；从整包选部分时不得让未授权的高质量集被覆盖。
- 完结后模式可选继续分集/整季，转换不得抹去每集画像。
- 整季模式：要求覆盖声明的目标季范围，逐集不下降且至少改善一集或满足特效例外；真实覆盖从种子文件清单核验，不只看标题Complete。
- 已有内容缺证据时不得将任意整包视为升级；范围未知/解析失败不能回退全种。
- 多集一个视频是一个资产映射多个目标；它跨越被排除或不应覆盖的集时不能假装只取半个文件。按整文件安全判定或换候选。
- 同一infohash可覆盖多个计划，但必须协调共享任务、wanted集合和实际已完成范围，不能各自改掉对方的选择。

排名用于同一轮候选优先级，目标覆盖用于计划组合；不必求全局最优复杂算法。明确策略为确定性优先排序＋保守覆盖选择＋失败尝试下一合格候选，保证可解释和可重放。

### 7.2 三类等待与失败冷却分开

| 机制 | 起算依据 | 作用与限制 |
|---|---|---|
| 候选观察期 | 本轮首次本地观察到合格且对目标有价值的候选 | 下载前积累候选，有基础等待、质量稳定窗口和最长等待；不因重复RSS重置。 |
| 秒传重试 | 仍有效计划的具体文件上次尝试与有效未命中计数 | 只处理传输；不是新的质量观察期，也不保证多等一定成功。被取代后停止。 |
| 升级冷却 | 该目标最近一次由本插件流程确认入库的时间 | 暂缓下一轮质量/证据升级；不阻止其他缺集、失败恢复或当前计划收尾。 |
| 失败冷却 | 明确失败及失败原因 | 避免重复选坏资源或请求故障服务；不冒充成功入库后的升级冷却。 |

电影/剧集的整体洗版期限、单次执行超时与以上时钟各自独立。读取元数据、路径改名、策略重算、RSS重复推送、定时器重建均不能当作成功升级来续时。等待期持续接收并去重候选，不停止RSS采集。

所有新数值参数在配置中显式设置；示例中的20/30/60分钟不是用户实测发布规律或强制默认。观察、升级冷却可关闭；允许提前执行的配置也必须明确。配置缺失/不合法要提示，不能默认为无限等待或放宽准入。

### 7.3 下载前候选观察期

按TargetUnit保存`first_eligible_seen_at`、`last_quality_improved_at`、当前可用首选和截止时间。时钟使用本地实际发现时间；站点pubdate另存用于诊断，不能用不可信/过旧的发布时间倒算等待已完成。

在开启观察时，建议确定性合同：

```text
D_observe = min(t_first + W_max,
                max(t_first + W_base, t_last_better + W_quiet))
```

`0 ≤ W_base ≤ W_max`，`W_quiet ≥ 0`；开启时`W_max`必须有限且大于0。同一轮首见时间保持不变；只有按当前策略真正改善首选质量、或命中已批准的特效证据升级时，才推进`t_last_better`。同质量转站、重复infohash、仅做种数变化不延长窗口。质量比较规则与“等多久”分离。

到达截止时间意味着必须重新评估并尝试执行合格计划，而非无条件下载：候选已删除、身份错误、被排除、服务异常仍须拒绝/延期并解释。新数据不得让本轮最长观察期限无限后移。

仅在明确配置的目标规格已满足时可提前结束观察；用户“立即下载”可越过观察/冷却，但仍须执行准入、身份、文件选择、占用与发布安全检查。不能把某资源原生100分当作必然达到目标。

不同集分别计时；合并整包不能借已成熟的E01绕过E02尚未成熟的观察/冷却，除非其明确目标达标提前规则也满足。不能安全只取成熟目标时等待或换候选。不会等待整部连载完结。

### 7.4 下载进程感知与受控改选

分别保存整任务和计划文件的已完成字节、进度、速度/剩余量/预计时间（接口实际提供时）、客户端状态、有效进展时间及采样时间。未知字段不伪造为0；计划只取E07时，不用整季百分比代替E07实际进度。

| 当前阶段 | 更优候选到来时的合同 |
|---|---|
| OBSERVING／尚未提交 | 更新首选；到期时选择仍合格者，不预先创建多个下载任务。 |
| 已排队但未开始 | 满足策略时先撤销旧执行许可/安全停止，再切换计划。 |
| 正在正常下载 | 默认继续当前计划，只保留待评估首选；显式开启早期抢占后才根据改善维度、实际已下载字节、剩余时间和成本作有限切换。 |
| 长时间无有效进展或确认失败 | 走已配置失败恢复/换源；排队、人工暂停、校验、限速和断连不自动归为坏种子。 |
| 本地完成／等待字幕／等待秒传／已在暂存区 | 满足观察与切换条件后可以取代；不是必须等旧文件成功上传才允许更优计划前进。 |
| CD2普通上传正在读取 | 可以先撤销旧交付权，但旧上传/读取须安全停止或隔离收尾；禁止提前清理仍可能被请求的源文件。 |
| PUBLISHING／交付结果不明／已交给Symedia | 不自动抢占交付权；先确认旧动作最终结果，再允许后继目标发布。 |

“出现更优候选”只更新候选池，不等于已经选定替代、更不等于入库。正式改选前复核候选身份、准入、文件范围、排除、可执行配置及本轮预算；不声称已知尚未下载文件能否秒传。

质量排序仍为第6节的词典序；进度/成本只决定是否值得现在切换，不把低画质靠成本加分变成质量更优。暂时更易秒传也不能让低版本覆盖已经确认的高版本。

### 7.5 交付权与外部操作状态分离

每个TargetUnit只有一个有效的`(owner_plan_id, generation)`。规划完成、调用下载器之前原子认领目标；成功取得下载hash后的回调只补执行结果，不能负责第一次占用。同一事务认领整包实际覆盖的全部目标；冲突按确定顺序处理，不能形成部分占用死锁。

建议将“计划是否有效”与“传输走到哪一步”分成正交状态：

- 计划授权：ACTIVE／SUPERSEDED／CANCELLED／COMPLETED。部分失效保存在plan_target，保留原因、前后计划和代次。
- 执行/传输：待提交、下载中、待齐套、RAPID_WAIT、RAPID_IN_FLIGHT、CD2_UPLOADING、REMOTE_VERIFIED、READY_TO_PUBLISH等。
- 外部交付：NOT_SENT／PUBLISHING／PUBLISH_OUTCOME_UNKNOWN／HANDED_OFF／INGEST_CONFIRMED。

以上为拟实现枚举，具体命名可调整，但不可用一个status同时代替授权和远端事实。旧计划变成SUPERSEDED后，外部请求可能尚未结束；它只能登记结果、查询和清理，不能因返回成功恢复ACTIVE或获得发布许可。

### 7.6 等待秒传中的计划取代事务

只有尚未进入PUBLISHING/未知交付屏障时，旧目标可经已配置调度策略被取代；秒传已经成功但仍在暂存中也可取代。已登记发布意图但是否发出未知时同样先核对，不能只凭暂时看不到文件判未发送。取代顺序如下：

1. 持久化已通过核验的替代计划B、目标范围、理由和策略版本。发现B但未选定时，不删除A的成果。
2. 短事务比较A的owner/generation及交付阶段；仅在未进入交付屏障时，将相应目标授权原子转给B、递增generation，并写A的SUPERSEDED记录及待取消/清理动作。
3. 取消A尚未发出的秒传定时重试、CD2普通上传回退和发布待办。不能只从内存定时器移除；工作队列、重启恢复、目录补扫都须查询授权状态。
4. A已发出的秒传请求可能成功；准确保存其本次暂存对象及Hash回执，但结果只供收尾，不发布。它失败也不触发自动慢传。未核实的在飞请求与旧读取进入独立的可恢复收尾队列。
5. B是唯一有效的新计划。旧请求与B若均使用独立暂存位置，可允许旧隔离请求结束，不强制等它拖几天才调度B；旧目标不得再发新的传输工作。共享下载任务/资产或外部读取未能安全隔离时，B在必要边界等待而非冒险操作。
6. 按第11节明确配置清理A的监控副本和未发布暂存；可保留为备用，但不是强制。共享资产仍有有效引用时不删。

每次秒传尝试、创建CD2任务、恢复下载和准备发布都检查owner/generation；已经排队的旧动作也同样检查。传输RPC在放行前先登记所属代次的attempt/in-flight意图，和取代事务确定先后：取代后未被放行的动作不再发出，已放行者按可能迟到的隔离操作收尾。取消本地任务不保证撤回已发出的远端RPC，故必须保留迟到结果的归属。

**SUPERSEDED不是永久黑名单。**目录扫描/MP再次整理/重启不能复活旧计划。新计划失败后，只有新的、符合当前在库基线和排除条件的显式规划才可重用旧资源；不得恢复旧定时器。若旧本地数据已按配置清理，说明可能需要重新下载，不伪造可恢复文件。

逐集取代不能无条件作废整季其他集。A的E07被B取代、E08仍有效时，只撤销E07授权；共享下载器wanted集合不能被错误清空。含E07/E08的旧交付目录不能原样整夹发布：把仍有效且可独立分离的资产生成经过核验的新批次，更新共享引用；无法安全拆开则暂停该交付，不能牺牲E08、擅自再下载或覆盖已不准交付的E07。双集物理视频依第7.1节作为不可分割资产处理。

### 7.7 入库后的升级冷却

按TargetUnit持久化`last_ingest_confirmed_at`和`cooldown_until`，从本插件确认当前有效版本入库时起算；不是下载提交、视频下载完成、秒传成功、CD2可见或扫描时间。首次仅导入旧库档案不伪装成刚完成了一次升级。

冷却期间继续收集/去重更优候选，但不为同目标创建下一轮升级下载。期满重新评估当时最佳合格候选，不逐个执行冷却期积累的中间版本。可将观察窗口与冷却并行计时：通常最早自动决策时刻为`max(D_observe, cooldown_until)`，不在冷却到期后无条件再加完整观察期；失效候选和错误仍需核验。

不影响其他集首次补齐、已经批准计划的传输重试/取代/收尾，以及必要字幕补传。确认媒体无效或明确缺失的修复可按修复策略处理，不能因普通升级CD拒绝恢复可用性。越过CD不越过交付屏障或收录底线。

同质量PGS→明确特效仍只允许一次；未成功的重试不重置该证据账本。SIDECAR_SUPPLEMENT和单纯补齐来源证据不默认重置普通质量升级冷却。

一次性RSS任务成功后立即结束，冷却保留在目标档案而非已结束任务行；下一次机会仍遵守冷却，但不重新打开几十天的持续观察期。

### 7.8 防止无限追逐与诊断

配置本轮连续取代预算（次数或时间上限）及独立失败重试/换源预算。预算沿用同一业务机会及其计划血缘，不能通过新建plan、重复RSS、进程重启清零。默认不在正常下载中持续抢占；等待秒传取代也不是每个微小改善立即重下。

达到取代预算时，不继续追逐后续候选，优先把仍符合准入/防降级条件的有效计划完成。已选候选失效则走独立的有界失败恢复或待处理；不能为避免饥饿强行发布低于当前库的文件、回用明确排除资源或丢掉必要字幕。

界面解释区分：观察未到、冷却未到、在途占用、更优候选待评估、旧操作收尾、计划已取代、交付结果不明、服务故障、换源预算耗尽。不强制增加LLM预测或自动学习发布规律；可记录首见/发布时间及间隔供诊断，样本和抓取延迟不足时不据此自动更改策略。

## 8. 严格文件清单执行适配

### 8.1 为什么不能只传episodes

历史V2核验发现过qB无法识别集数仍恢复、无集号附件漏选、同名同大小领养等风险。它们在本版是必须在V3重新执行的回归场景，**不是V3当前仍有这些bug的结论**。V3公开download_single及self.download分派可作适配基础；先证明当前原生严格选文件能力是否满足合同，能满足就复用，缺口才窄封装。[V3DL01；历史MP05、MP06、MP07]

### 8.2 必需执行合同

`ExecutionPlan`冻结并保存：目标身份、候选资源键、种子infohash、策略版本、当前库版本快照、要替换的旧版本、视频/字幕/必要附件的索引-相对路径-字节数、各文件覆盖季集、下载器和保存目录、动作理由、创建时间、重试预算与幂等键。

提交顺序：

1. 通过MP既有种子获取/解析工具取得文件表；规范化并校验路径，拒绝路径穿越、未知非法文件项和空选择。
2. 下载器已有相同infohash时先核验归属、保存布局和选择范围；不按同名同大小自动接管其他任务。不属于本插件且会受选择变化影响时暂停本计划并提示。
3. 使用MP已配置的qB/TR客户端以暂停状态添加或安全领养任务，保存准确的下载器＋infohash/任务标识。
4. 按清单设置视频、所需字幕及必要依赖wanted/priority；索引与实际文件路径/大小交叉核对，不能只假定客户端索引与解析顺序相同。
5. 回读完整wanted/priority集合，必须包含全部计划文件且不包含未授权视频；有任何歧义不启动。
6. 再核验计划持有当前目标owner/generation、未新增排除、没有冲突或未知的旧发布结果，然后恢复下载；候选首选变化本身不越过正式取代事务。
7. 记录实际接受状态；返回hash但仍暂停/选集失败不标作已成功下载。

只支持经能力核验的下载器/文件形式；磁力未获得文件表时不得绕过预检直接全量下载，待元数据可安全取得再处理或报告不支持。跨季包要以季＋集完整映射，不能仅按集号误选另一季。

### 8.3 复用MP而不修改核心

推荐插件专用`PlannedDownloadChain`实例，覆盖`download(...)`将执行委托给上述严格适配，保留上层`download_single(...)`的路径解析、通知和记录能力；其运行只由已持久化计划调用。禁止对`DownloadChain`全局类赋值或劫持所有download模块。

这是**本设计提出的实现形态**，不是声称上游已有该类。Codex需验证V3公开DownloadChain的签名、运行装配与`self.download`分派，不能直接继承私有owner类作为稳定API。若基类DownloadFiles过滤遗漏无集号字幕，插件文件清单仍是权威，并通过现有记录接口补齐；整理前使用清单守卫拒绝非计划/未完成视频进入监控目录。

MP下载后异步字幕动作应被追踪或封装为同一计划的配套文件任务，不能把DownloadAdded当成全部字幕已准备好。不得为省事关闭用户已有字幕功能然后漏掉资产，也不新写无关字幕站爬虫。

上层所传`episodes`仅作为范围及历史元数据，真正执行以核验后的文件表为准。TV空集合必须在调用前被拦截，不能借用Python假值退化为全种下载。

### 8.4 下载完成观察

读取宿主下载器状态和实际选中文件完成情况，并定期采样第7.4节所需的字节/进展/状态。部分做种、任务重新选集、恢复已有文件均检查本次文件清单，不把种子总体进度当唯一证据。下载任务重复回调只推进一次状态；被取代的旧回调仅更新旧操作事实，不重新激活计划。提交占用已经在调用下载器之前完成。

独立策略不取消BT客户端的完整性校验；也不把选中部分视频后出现的必要边界piece缓存当“已授权导入整包”。只有清单内且完成的资产可进入后续交付。

## 9. 媒体档案、来源与路径关联

### 9.1 档案独立于订阅生命周期

持久化数据库保存当前/历史版本、每文件内容标识、发布证据、Emby/CD2/115位置、目标关联和策略结果。无活动订阅也能建档和参与授权库的被动监控。旧库缺原下载历史不是重新下载前提；从Emby和当前文件事实建档，新下载从源头完善来源链。

文件Hash用于字节一致性，对应媒体ID和字幕声明靠各自证据。不能因两文件技术属性相似就继承发布声明，也不能靠SHA1自动证明刮削身份正确。

### 9.2 当前版本数据源

- Emby：服务、库ID、电影/系列及Episode Item、MediaSources、MediaStreams、关联Path等。
- 当前文件名及路径：来源、发布组、HQ等，按严格技术段识别。
- 下载/整理/上传记录：原始发布标题、副标题、实际选文件、完整SHA1、云端目标。
- CD2/115：当前路径对象、大小和服务给出的完整SHA1。

不存在与读取失败、关联歧义、信息过期分开。全量同步要分页、完成快照后再确认删除；一次空页、401、网络超时、Emby重扫导致Item换ID不自动清空档案。对同路径替换核验内容变化；仅字幕Title修正记信息修订，不机械记一次真实洗版。

### 9.3 两段路径映射：用户实测布局

**这三种STRM相关路径不是同一个命名空间，前两种是文本文件，内容才指向视频。**

宿主STRM目录：

```text
/vol2/1000/strm/115/
```

Emby STRM前缀：

```text
/mnt/nvme0n1-5/AutoSymlink/strm/
```

建议新增到MP的只读挂载前缀（提议值，尚未部署）：

```text
/archive-input/strm/115/
```

第一段配置：`Emby前缀 → MP可读前缀`，读取实际STRM文本。宿主部署将`/vol2/1000/strm/115/`只读挂载到该MP前缀；不要求MP挂载整个cloudfs视频树。

第二段配置：

```text
STRM视频目标前缀：
/vol3/1000/docker/clouddrive2/CloudNAS/CloudDrive/115/

CD2内部前缀：
/115/
```

每组映射还绑定Emby服务、适用库、CD2服务与115账户。不能根据`CloudAPI.name=115open`推导路径为`/115open/`。

样本相对路径（视频）：

```text
media/TvShows/国产剧/180天重启计划 (2025) {tmdb-273701}/Season 1/180天重启计划.2025.S01E01.2160p.WEB-DL.H.265.AAC.mp4
```

样本真实返回：

```json
{
  "cd2_path_prefix": "/115/",
  "id": "3324548941069344898",
  "size": 3118741031,
  "sha1": "1562FB08EB99ABE510020D322420E0BA8E687104",
  "isCloudFile": true,
  "isLocal": false,
  "CloudAPI_name": "115open",
  "originalPath": "",
  "CloudAPI_path": ""
}
```

FindFileByPath和父目录GetSubFiles的该样本输出一致；没有强制刷新，也没有与样本的某次本地下载比较。因此当前只证明接口能返回Hash/大小和这组路径可对应。

### 9.4 解析要求

按服务/库和目录边界的最长前缀匹配，不全局replace，不直接用STRM扩展名改成mkv/mp4。保留中文、空格和花括号。清理BOM/换行但不随意转义本地路径；多个内容行或格式不支持给出错误。不得把内容路径在MP上当真实文件打开来算Hash。

支持普通本地STRM为此环境主路径。优先使用Emby提供的当前MediaSource目标，若只提供STRM位置则读取只读挂载。读取大小上限、授权根目录、真实路径/符号链接安全检查、明确的路径映射版本必须存在。读取前后和提交关联前复核STRM未变化；变化则重试，不把过期结果写为当前。

通过CD2原始CloudDriveFile读取`fileHashes[2]`，不要仅用丢掉Hash的简化FileItem。CD2缺Hash则用已授权115对象查询补齐；禁止对远端视频自动全量sha1sum。CD2对象ID与115文件ID分别作为字符串保存，不未经核对混为一键。

### 9.5 最终入库确认

确认顺序为：目标媒体/季集正确→当前STRM播放来源定位→云端Hash/大小与获授权计划相符→必要字幕及其他资产已对应→Emby媒体流已刷新且无关键冲突。对等待入库的目标主动定向查询，不只等“新增媒体”通知。STRM文本不变但其目标内容变化也需核验；计划代次过期的查询结果不得覆盖当前档案或重置冷却。已发布计划的真实迟到结果要记录并先完成旧发布对账，不能当作新计划成功。

原地移动通常保持内容；复制产生新对象时，只要目标定位和内容一致可记新副本，不虚构移动历史。重封装/改字幕等改变内容不能沿用原Hash证明；当前传输模块不做这些转换，外部改变需记录/提示重新验证。

多版本分别确认；一个旧高分副本仍存在不导致低分副本被误作整个目标状态。只有仍在库有效最高版本决定当前质量。严格的“整个视频可播放”验证另于元数据核对，本方案不通过全库播放下载来保证。

## 10. 监控目录、115暂存与交付

### 10.1 目录规则

每条可配置：启用、本地监控根、115暂存根、115交付根、115账户/存储引用、CD2服务/对应根、可选实时事件、启动补扫与定期覆盖全范围的对账、文件稳定窗口、秒传次数/间隔、普通上传回退与单文件上限、成功清理/取代清理和通知。自动运行不能把实时事件作为唯一发现通道；周期可调，不能同时关闭全部可靠发现/恢复方式。

本地输入就是MP已整理输出；插件只保存其相对结构并绑定身份，不再次制定媒体最终命名。来源是复制/移动/软链接/硬链接由用户MP配置决定，本插件不管理做种策略。

本地输入与STRM输出、视频cloudfs目录严格分开，不能误把STRM/挂载媒体当成新下载反复上传。嵌套或重叠监控规则必须去重并明确归属，不能产生双重删除权。

### 10.2 清单与字幕齐套

以本次完成整理的一组文件建立清单；优先MP整理事件/记录，辅以文件稳定检查。没有外挂字幕可正常交付；已经识别出的必要字幕必须齐套；未唯一绑定的字幕保留结构、错误提示，不能乱配。

对一集视频匹配多个语言字幕；双集视频覆盖两集；IDX/SUB等成对资产、明确声明依赖的字体/附件保持依赖关系。字幕压缩包不是“已经有可用字幕”，只能使用经过验证的解包能力并防Zip Slip，否则保留待处理，不宣称特效已交付。

迟到字幕补充任务不重传视频、不重开质量洗版；目标版本在补传期间发生变化，重新确认关联。持续增长的剧集目录不能锁成一个等待大结局的大批次。

### 10.3 秒传与普通上传

每一文件计算一次可复用的完整SHA1及大小，记录计算前后的本地身份/mtime/size。变动则结果失效，不能上传一半更新的文件。重试前确认仍为同一内容；符号链接只为授权输入读目标，清理不追删目标。

每文件最多N次**有效秒传未命中**，间隔可配。认证、网络、限流与远端不可判定单列系统重试，不能消耗未命中次数后默默转普通上传。每次成功保存实际远端对象及查询核验结果。所有重试、回退和后续发布均绑定有效plan_target代次；第7.6节取代后立即禁止新尝试及慢传回退，迟到成功只登记旧暂存成果。秒传等待时长没有确定成功保证，不得永久挡住更优计划。

未命中达到上限：

- 普通上传回退关闭：保留本地/暂存状态并提示。
- 回退开启且该文件大小≤X GB：创建或接续唯一的CD2普通上传任务。
- 大小>X GB：禁止回退并报告；按单文件算，不按整文件夹合计。

单位明确：配置中的GB使用十进制10^9字节；若界面同时展示GiB，标明2^30，不混用。X为空代表需配置，不把0误作无限；若需要“无限”应有显式选项。

视频、字幕各自执行同一规则，不因字幕小自动绕过关闭的回退开关。策略可另设小文件快速允许配置，但必须显式。回退必须走指定CD2服务，不让借用的P115Api在未命中时自行走未批准的OSS上传。

CD2任务创建、进度、终态均持久化。来源文件在CD2仍请求读取/Hash时不得删除。任务队列消失不作为成功证据，核验115实际对象。保存了远端对象但CD2刷新失败，只重试刷新，不重复上传。

### 10.4 隔离暂存取代多文件hold假设

暂存与交付必须在同一115账户，暂存树明确位于Symedia监控/整理范围之外；单靠点号名字、未发通知或文件后缀不足以保证隔离。

每DeliveryBundle使用独立批次目录和完整相对结构。视频先秒传成功可以留在暂存，等必要字幕；只重试仍有效计划的未完成项。N次耗尽且没有回退时，未明确放弃的任务保留部分成果，不破坏正式旧版，不默认按年龄清空失败暂存。经用户操作或已启用策略正式取代/放弃后，可按第11.4节清理确切拥有的旧成果；两种情况不可混淆。

齐套之后逐文件校验远端完整SHA1＋大小，并通过第10.7节有效计划与防降级检查，才将**已准备好的独立目录**交付到配置入口。准备齐套不自动获得交付权。目标冲突不能静默合并两个批次；使用确定、幂等且可恢复的批次身份。路径命名属于传输包装，不替代Symedia的最终媒体命名。

这是**发布屏障**，不是宣称115/CD2提供跨所有文件与下游消费者的ACID原子事务。移动后核验落点，刷新受影响父目录；是否触发Symedia完整处理是必须实机测试的合同。

### 10.5 外部副作用可恢复

本地事务保存远端确认与Outbox刷新/交付待办，再执行外部RPC。超时后先核验实际状态再重试。异步回调含重复/乱序时只允许合法状态推进，不把原先取消操作后来到达的成功事件发布成当前版。

失败暂存仅清理本插件确切拥有的批次。已经发布且被Symedia移动的文件不能因批次旧路径消失就判定上传失败；应通过对象/内容和最终来源收敛。不能声称所有外部操作恰好执行一次，目标是幂等重试和明确结果。

### 10.6 丢事件恢复：通知只加速，不承担完整性

**验收主线：完全关闭本插件inotify，并丢弃MP整理广播/Emby Webhook，仍可依赖持续存在的文件、持久化记录和主动查询完成本插件负责的步骤。**端到端通过还以Symedia存在且已验证补处理能力为条件，不能将自身可恢复等同于所有外部消费者自动恢复。

| 层 | 可靠驱动 | 通知的作用 |
|---|---|---|
| MP已整理本地目录 | 初始/重启扫描、定期完整范围核对、已记录整理任务的路径补查 | inotify/整理通知仅把路径加入待核对队列。 |
| 115暂存与交付 | 上传回执和持久化outbox；按对象/批次主动查Hash、大小、位置和外部结果 | 不等本地CREATE事件来发现自己刚上传的文件。 |
| CD2可见性 | 主动刷新受影响目录、按已知对象/路径查询 | 刷新已执行、文件已可见、通知已产生、Symedia已消费四个事实分开。 |
| STRM/Emby当前版本 | 在途目标定向查询、低频完整档案对账、两段映射及Hash核验 | STRM修改/新增媒体通知只触发提前查询。 |
| Symedia漏处理 | 核验现有周期扫描、指定目录补扫或真实任务入口中的至少一种 | 不能将重复CD2刷新当作必定重放同一新增通知。 |

本地范围扫描不依赖“收到事件才标脏”，也不只看顶层mtime推断所有子目录未变。可优先处理活跃目录，但在配置周期内必须遍历已授权本地监控范围；分批游标、失败路径、完整扫描水位持久化。未完成快照、目录读错、挂载消失不得据此批量标文件已删。识别新文件进入统一幂等队列，不在扫描回调里直接上传。

inotify关闭或失效是允许的降级模式。若启用，必须处理IN_Q_OVERFLOW、监听注册失败/限额、目录移动/删除/替换、新子目录建立竞态和卸载/重新挂载；新目录添加/核对监听必须配合补内容快照，并覆盖两者间窗口的再扫描。CREATE、MOVED_TO、链接加入等不能都要求等CLOSE_WRITE才处理。记录监听健康并触发有界补扫，增大监听参数不是恢复证明。

不要递归遍历整个cloudfs视频树来替代云端对账，更不要重读远端视频算Hash。云端变化可绕过本地路径；按已知任务对象及受影响父目录查询，Emby旧档案按页低频巡检。自己的主动上传结果不依赖远端触发inotify。

Symedia恢复能力在上线前形成能力矩阵：实际版本、目录监控/缓存配置、已有扫描入口、失败重试和实测证据。找不到自动补处理入口时进入`WAIT_CONSUMER/BLOCKED_CONSUMER`并提示，不声称无人值守闭环已通过；可保留“已交付，待人工补扫”的诚实状态。禁止虚构Symedia接口，禁止靠反复改名、删建文件或重传来制造事件。CD2再次刷新不保证给已知文件再发相同事件，具体行为交实机测试。

恢复保证的前提是目标文件/远端状态仍然可查询、授权服务最终恢复、扫描能覆盖范围且消费者能够补处理。瞬时出现又消失、被其他系统永久删除或外部消费者没有恢复入口的情况，不作“绝不漏”的保证。周期对账本身超时或长期滞后须可见，不能静默显示无新文件。

### 10.7 交付前重评估与串行发布屏障

只有当前有效计划可以向Symedia消费目录发布。发布前重新核对：媒体/季集与本批资产、owner/generation、候选排除、当前策略、当前有效版本及最近确认状态、必要字幕齐套与远端Hash/大小。批准下载不构成永久批准覆盖。

质量或证据已被当前库同等满足时不重复交付；低于当前在库版本时禁止发布。缺失或数据查询错误分别处理，不能为清空积压而放行。正在执行的外部变更无法观察时，不承诺能够抵御所有绕过本插件的手动覆盖。

发布检查与进入发布步骤必须可序列化：短事务登记唯一PublishAttempt，比较并锁定其所有目标授权，转入`PUBLISHING`，之后才发外部移动请求。计划取代与这一状态转换共享同一目标冲突域，不能“检查A有效→另一线程取代A→旧线程仍移动”。

`PUBLISHING`之后，任何超时/网络错误/worker退出先记`PUBLISH_OUTCOME_UNKNOWN`并查询实际位置。**generation只约束本插件，不会使已经发给115/CD2/Symedia的RPC自动失效。**租约到期不能释放发布屏障；旧进程可能仍提交，须确认它已停止、原操作已完成或能够证明从未发出且以后也不会发出，才能安全重试/改选。

交付成功后状态为`HANDED_OFF`，保持同目标发布屏障，直到该计划的下游处理与当前版本得到确认，或者有证据证明旧内容不再可能迟到发布。单独观测到另一高版本或只是看不到旧入口文件都不等于旧动作已解决。未知交付不得让B发布或自行降级为未上传并重传A。

被SUPERSEDED的旧请求成功，只在它独立的暂存位置形成待核验/清理结果，不移动进消费目录、不发送用于发布它的通知、不确认当前版本、不重置冷却。批次部分目标已取代时按第7.6节拆分/等待，不能原目录整体穿过屏障。

这些保证只覆盖经过本插件控制的发布入口；未受管手动任务和外部容器可以改变媒体，检测到冲突时暂停相应受管操作并提示，不假定可以控制外部全部时序。

## 11. 本地清理与排除换源

### 11.1 成功交付后的清理

可配置删除监控目录中的已交付文件。条件：整组必要文件已在115核验、交付完成、关联和后续待办持久化。无需等待Emby扫描，但Emby确认仍是任务完成条件。

只处理清单中的同一个本地目录项；删除前核对原inode/目标/大小/mtime等身份，若变成新文件则停止旧清理。软链接只unlink链接，硬链接解除该位置，普通文件按授权清理；不得递归进入目录软链接或删链接目标。实际执行时用安全的目录句柄/不跟随链接策略防TOCTOU，不能只做字符串前缀判断。

目录仅在真正为空且属于本次清理范围时删除。其余未上传字幕/其他集保留。保种由MP组织方式决定；默认不对下载器源目录删数据，不改变H&R或Tracker策略。显式授权的下载器清理由第11.4节独立开关控制，不由监控目录清理隐含开启。

### 11.2 精确排除与自定义条件

支持站点＋种子ID、已知infohash、媒体/季/集范围、已知内容SHA1、条件规则等粒度。排除原因和有效期独立：用户手动明确排除可持续到撤销；时效故障冷却；永久内容否决不与接口临时故障混同。

条件可以读取候选资料、当前版本、策略、任务状态、历史失败以及已经取得的文件信息。未知候选Hash不能预先套用Hash条件。明确排除不被“空池恢复”、其他allow或同分特效例外抵消。

ResourceSelection是原生补充防线；独立候选池在生成计划前同样执行排除。ResourceDownload和严格执行器恢复前再检查，以防筛选后新增排除。不得默认拦截无关手工下载。

### 11.3 排除并换源的操作事务

用户可选择“仅不再选该资源”或“排除并放弃本次文件后换源”。第二项执行：

1. 持久化排除和取消意图；停止新一轮重复选中。
2. 停止/取消相关下载后交付任务及CD2读取；未确认停止不删除仍被读取文件。
3. 清理明确授权的监控目录文件和本插件未发布暂存残留。**这是用户明确放弃的例外清理，不要求这些失败文件先成功上传。**
4. 旧有效在库版本保持；撤销失败在途计划的贡献，不整季清零、不使用旧宿主分数伪造真实状态。
5. 只为受影响目标生成新的候选搜索与执行计划，次数有界，沿用准入底线。

防止原下载任务被MP再次整理回监控目录：保存该任务/文件的排除并在整理准入和本地监控中校验。下载器任务删除数据不是默认动作；需要额外授权并只限明确归属，不能按作品名删所有种子。

若已发布/已入库，再排除来源默认不删当前可播放文件。明确“当前版本无效”可以从有效基线中剔除并计划替换；正式媒体物理删除不通过普通排除按钮隐含执行。

一个种子只有部分集失败，只有失败TargetUnit和相关资产受影响；共享字幕/字体等被其他成功单元引用时不能清理。恢复计划不创建同目标的竞争交付。

### 11.4 取代清理与下载器删除权限

清理原因和权限单独保存，不能从“任务失败”或“分较低”自动推导删除授权。

| 操作/原因 | 允许条件 | 默认/边界 |
|---|---|---|
| 成功后清理监控目录 | 第11.1节远端核验、已交付与待办持久化 | 由目录规则显式启用。 |
| SUPERSEDED／明确放弃后清理监控目录 | 正式取代事务已提交，旧交付权已撤销，文件仍是登记对象且没有在读/共享依赖 | 独立可配；**不要求该放弃文件先上传成功**。保留作备用也可，不强制保留。 |
| 清理本插件未发布云端暂存 | 确认对象属于旧批次、无有效引用、在飞操作已收尾 | 不按路径猜；未确认远端结果先核验，不触及正式库。 |
| 停止/调整下载器中的受管任务或wanted | 为取消旧执行所必需且归属/共享范围明确 | 不等于删除任务或删除数据；不得伤害其他有效集、手动任务或保种状态。 |
| 移除下载器任务 | 用户单独开启相应权限，且任务专属、取消范围完整 | `remove_downloader_task_enabled=false`为默认；可与停止分开。 |
| 删除下载器源数据 | 用户额外明确开启，任务/文件专属、无共享/未完成引用、满足停止与授权检查 | **`delete_downloader_data_enabled=false`为默认**；不是监控清理开关的附带动作。 |

共享整季任务仅E07被取代时，不得调用“删除任务及所有数据”破坏E08；当前客户端无法安全按文件清理则跳过该破坏动作并说明。复制、移动、硬链接、软链接进入监控目录均按登记目录项处理，不假定“已经整理”天然证明源文件不会被做种。

清理必须等待实际源读取已终止：CD2 Remote Upload仍可能请求读取/Hash、旧网络回调尚未收尾时，取消标记不是可删证据。身份不明、文件换了内容、路径被新计划复用或有其他引用时不删；必要时保留读租约和清理待办。

监控副本已按取代配置删除、新候选随后失败时，界面明确说明旧副本不存在，新的恢复计划可能需要重新下载。SUPERSEDED与永久Exclusion分开；旧扫描项、旧上传定时器或旧DownloadAdded不得复活。未明确放弃的失败任务仍按第10节保留成果，不默认年龄清理。

## 12. 生命周期与一次性RSS

### 12.1 持续任务

状态至少区分：目标待确认、持续补齐/升级、用户暂停、到期停止积极升级、被动监控、用户停止。计划状态与目标状态分离；在途目标不能冒充已入库。

受管剧集建立即逐集处理。范围未闭合或仍有应补集数时，不因升级时限届满停止补缺；也不把“已播的都齐了”当整季已完结。实际结束范围依赖元数据与显式总集数/用户约束，不仅看剧集系列是否Ended（系列仍续作也可能当前季已完成）。未知发布日期不能无限猜未来剧集。

完结后模式可选分集或整季；转换只改计划方式，不销毁逐集事实、不强制写原生best_version_full。用户可切换并预览会改变哪些动作。

### 12.2 可配置期限

电影、剧集分别设置天数，0无限；自动创建范围关闭不停止已受管任务的期限管理。

起算方式作为明确配置而非隐式：例如“完结且收齐后固定窗口”或“最后一次确认交付/升级后空闲窗口”，采用增强助手可用的思路但不继承其只管理全集/关闭即不巡检的耦合。界面展示所用anchor与截止时间。扫描、重新评分、重命名不重置升级时钟。

期限到达：不新增积极升级，已有获授权在途计划按独立执行超时策略收敛，继续必要补缺。退出记录原因与实际质量，不能伪造100。主动期达到配置目标可提前停止积极搜索，但不无依据宣称未来不会有更好版本。

### 12.3 被动范围

从MP配置的Emby服务读取实际媒体库供选择，以服务＋库ID保存。选中库里已有但未曾在MP订阅的作品可参与；未选中的不自动下载。用户明确停止覆盖库级默认。库内删除须可靠确认，不能因旧历史一直复活已移除作品。

资源供给由插件独立定时服务读取/刷新宿主站点原语，不依赖原生仍有活动订阅。每站有稳定去重游标、抓取水位和失败状态；不能静默把长期RSS失败解释成没有新资源。

### 12.4 一次性唤醒

发现合格且改善当前目标的资源，建立`ONESHOT`任务：目标集/旧版本快照/期望比较结果及本轮候选窗口明确。可按策略补搜并选择更合适候选，但不得扩为无限期追踪整部剧。

成功条件：所有本轮目标已在库核验为所批准的改善或等价更优结果；同分特效需要来源声明关联。成功后立即归档本轮，保留当前档案与被动监控，不要求最高分、不重开常规N天观察期。

失败使用同一任务有限重试/换源和失败冷却；重复RSS、跨站重复及服务重启不生成多个业务机会。候选观察与在途取代沿用本轮scope和预算，不因换plan重开长期任务。成功后的升级冷却写入TargetSchedule，ONESHOT归档后仍有效。存在其他活动受管任务时合并目标/排队，不再建竞争交付；不改写别人的活动订阅。

## 13. 数据库、并发与性能

### 13.1 存储原则

使用`get_data_path()`下插件自有的独立SQLite数据仓库，不在115/cloudfs上存DB、不拿MP订阅表作为唯一档案。该库仅保存插件拥有的数据，由自身Repository管理短事务；与V3宿主Oper之间没有跨库原子承诺。不得把宿主Session/Model引入此库，备份应分别覆盖插件库和需要的宿主配置。事务短、迁移有版本、备份可恢复。原始媒体流/声明可存JSON，常用索引字段单列。

### 13.2 计划并发

以TargetUnit及相关物理资产为范围持久化**唯一有效交付权**，在下载提交之前原子认领；下载完成不释放。不同集可并行，整包/单集/双集使用实际覆盖范围的同一冲突域。等待秒传的旧计划不永久持锁；交付前可以按第7.6节将授权事务性转给新计划，旧操作只保留隔离收尾权。

认领、取代和进入PUBLISHING共享状态比较与事务边界；批次范围中的全部目标授权必须一致或具有明确的逐目标代次向量。读取old plan快照后不能在锁外无条件执行发布。generation不是远端系统的fencing token，不对已经发出的外部副作用声称可撤销。

长操作不能持有整库事务。lease用于工作者恢复，不代替业务授权；lease超时不是旧进程/远端操作已停止的证明。PUBLISHING、PUBLISH_OUTCOME_UNKNOWN、HANDED_OFF的后继交付须先查明旧操作结果和消费者状态，不能简单重置锁。对仍在隔离暂存中收尾的SUPERSEDED请求，新计划可在不共享危险资源的条件下继续；所有旧回调只能更新旧操作记录。

外部副作用采用“持久化意图→执行→查询验证→提交结果”，可重复投递但结果幂等。禁止拿“恰好执行一次”当没有证据的保证。

### 13.3 规模与负载

此前媒体规模约两千电影、两千剧集、五万集，作为容量参考。首次扫描分页续跑；本地已整理监控范围周期全覆盖，Emby变动/定向查询与低频全量对账结合；inotify、Webhook和MP广播只是加速，不是唯一真值。各层分别保存最后成功水位、积压和失败，不把不完整扫描解释成删除。不要每轮RSS扫描全库、遍历完整cloudfs、逐文件重新ffprobe或读取远端视频。

Hash仅本地完整文件首次稳定时计算，上传重试可复用；策略变化主要重算数据库事实。设置每服务并发、API速率、队列长度和磁盘水位，不因DB暂不可用放开执行。性能结果由实测报告，不直接称“几万集很轻松”。

## 15. 迁移、兼容与外部代码复用

首次迁移读取实机版本、配置导出、当前活动/历史订阅及库；与本包输入参考比较差异。将既有偏好转为独立策略，展示原生条件不再生效的范围；未受管原生配置不清空。

旧episode_priority=100等仅作历史诊断，不把它们迁移为真实质量。实机已知版本从Emby/文件名建档，按独立策略比较。原生已有下载任务先对账与领养，不能为新架构立即重复下载。

任何旧稿实现或旧插件数据迁入本版时，在途计划与暂存/已交付对象先盘点：不能因新增generation、观察时钟或权限字段就把所有任务重新调度、取代或删除。找不到原首见/入库时间则记录迁移依据，不伪造最近成功、不重置全部期限。默认关闭的下载器删除权限不能从旧的监控清理开关推导；数值未配置提示确认，不覆盖用户已有设置。

参考模块复用重点：优先V3版本；历史REF01–REF08只作算法/字段追溯。[V3DOC01、DDSV301、DDSV302、UAI01、URANK01]

- p115disk：优先DDS的plugins.v3实现；认证接入、SHA1挑战与API；提取秒传接口，不能继承未授权自动慢传。
- clouddrivedisk：优先DDS的plugins.v3实现；CD2已认证客户端、上传/刷新/查询；保留原始Hash，追加远端成功核验。
- p115strmhelper：只借鉴已核实的等待/索引算法，所固定DDS提交未发现同名V3目录，不能臆造V3实现；按V3重写适配，不依赖其STRM/FUSE/302功能，不引入P115Center遥测。
- subscribeassistantenhanced：事件/计时/排除/任务结构参考；不继承固定100、强制全集、关闭创建就停期限、URL子串资源主键等行为。

复用应锁定依赖版本并核验实际许可，保留作者/来源/修改说明。DDS仓库根LICENSE为GPLv3文本；具体文件和引入库的许可逐项检查，不将整个第三方仓库无选择复制。不要把本项目包装成官方MP功能。

### 15.1 两个旧插件的迁移与切换

ChatGPTPlusUltra和DoubanRankPlusOptimized的旧配置/历史通过用户导出或已授权宿主公开入口读取；先备份与预览，再执行幂等导入，不要求在V3启动不兼容的旧插件才能读取数据。无需保存旧源码中的调度器实例或内存缓存。

逐字段映射和行为差异见《06_整合范围与配置迁移》。旧endpoint/key/proxy/customize_prompt和备份不能被默认值覆盖；密钥仅安全迁移或引用，不写入设计包/日志/公开导出。旧榜单所有来源、类型提示、目录模板、筛选和历史都给出对应去向；有歧义的旧unique/title记录不随意合并为最终身份。

旧历史“已添加订阅”不作实际成功证明（源代码未验证add回执）；和当前宿主壳/插件目标/Emby档案对账后链接。未识别/评分不符/年份不符保留原原因，同时允许有界重试或策略改版重新判定；不能全表清空后批量重建，也不能永久把失败当成功去重。

采用有回执的切换：新配置验证/导入完成 → 显示重叠旧功能 → 经用户确认停旧榜单调度与旧AI响应 → 开启对应内置功能 → 查询确认唯一处理者。中途失败保留步骤、停止新增副作用，不自动删除旧配置，也不并行启用两套作为“兜底”。切换触发源和实例ID记录，回退先停止新任务入口再恢复用户选择的旧功能。

不复制旧API的GET删除、在URL中打印迁移token、完整配置日志；历史管理统一走V3鉴权的修改接口。保留用户可用的远程导入/导出能力时，旧服务只读访问可兼容其旧协议，但敏感URL不能进入日志，目标主机明确授权。

所有交付功能统一设计和集成；开发内部顺序、TDD和逐步启用安全模式不等于削减为MVP。可并行开发独立模块，但共享模型、接口、状态语义先统一，不允许各模块自建不兼容的文件ID/任务状态。

## 16. 安全、错误与可观测性

- 错误分域：身份不符、准入拒绝、正常未注明、采集失败、暂时限流、内容秒传未命中、文件损坏、上传未知、映射错误、在库未刷新；不能一概记“失败”。
- 关键日志带task/plan/bundle/file/target id、策略版本、owner/generation、前后取代计划、publish attempt、观察/冷却依据、动作理由及耗时，不包含cookie/passkey/token/签名URL。
- UI/API管理动作沿用MP授权，不提供可匿名触发任意删除或路径查询入口。
- 可执行正则要限复杂度/时间，配置schema验证，网络调用设timeout/重试上限；没有数据时不以异常开通全部候选。
- 插件只请求为功能所需的数据，不把文件名/Hash上报第三方统计服务。
- 上游PT声明在用户信任模型下使用，但不能把其写进代码执行、命令、路径或未转义模板。
- 已上传确认且本地清理后，后续Symedia不按预期处理可继续主动对账并调用已验证的补扫；没有恢复能力时明确待处理，不把再次发送通知保证成成功。不能物理恢复被外部覆盖删除的旧视频，禁止把DB状态回滚叫做文件回滚。
- 自动抢占、取代后的清理只在明确配置和归属范围内执行；候选变更不是删除授权。处于交付结果不明时保持屏障，宁可报告阻塞，不以超时强解锁换取表面进度。
