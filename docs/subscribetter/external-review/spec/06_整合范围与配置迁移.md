# 整合范围、迁移映射与不继承的旧缺陷

**v1.2：subscriBetter / SubscriBetter / subscribetter，仅V3。**本页是主设计的补充映射表，不另开第二套规范。旧插件源码基线为`cbd770e364ec9a96a81fbfe9ac8d33abdb2bb1ba`，版本分别为1.4.2与1.0.7；实际用户配置可能不同，应读取导出并展示差异。

## 1. 三个来源如何组合

| 输入 | 保留/内置 | 不能原样继承 |
|---|---|---|
| ChatGPTPlusUltra | 文本依据name/year、API兼容传输、验证/缓存/请求合并/错误/统计/提示词备份、可选聊天 | 仅靠NameRecognize覆盖全部识别；旧Meta季集必正确；把unchanged诊断当拒绝；源130测试即新测试 |
| DoubanRankPlusOptimized | 作品榜单/自定义RSS、来源参数、筛选、多季、历史面板、导入导出 | best_version=0另造原生流程；失败永久已处理；未核add回执也记成功；@@TV等于数字尾号必是季 |
| 用户解析对话最终结论 | 启动安装两个Meta内部桥接包装，统一确定性纠错；可撤销、Python/Rust覆盖测试、定向缓存重解析 | 热路径LLM/网络、无上下文猜ID、到处替换MetaInfo引用、原地污染共享对象、全局清缓存 |

各模块可独立关闭或配置，但共同使用一个管理目标/计划/状态体系。关闭榜单只停止发现，不停止已有订阅；关闭AI不放宽身份；关闭热补丁不删除业务任务；插件整体STOPPED和具体目标STOPPED意图不受自动重新扫描影响。

输入与输出的title/season/episode必须区分：LLM输出只有name/year，宿主桥接附加字段来自经核验Meta，不是让模型扩大schema。旧函数看不到调用方完整org_meta，unchanged_current_title不能证明主程序无需重查。新内部调用有完整上下文时也应记录依据，不混同日志与身份事实。[UAI01–UAI03]

明确401才按鉴权政策禁key并有限换key；429与Retry-After不靠切key绕过；网络、格式、无名称分域；配置代次变化后旧请求只能收尾。保留普通聊天限制和会话隔离，但不提供新的Agent系统。

### 3.2 历史语义

保留旧状态字符串和时间/标题作为原始记录，不直接升级成目标事实。旧SUBSCRIPTION_ADDED可能没有成功回执；旧MEDIA_EXISTS不代表可比高质量；旧UNRECOGNIZED不是永久忽略理由。以可信媒体身份+季+剧集组与宿主目标/Emby档案重新关联，0/空/字符串None等旧ID为无效而非真实来源ID。

一个发现项可能产生多个季的intent，状态分别保存。一个季成功不把所有季标完成；历史展示删除不撤销运行中的任务。默认不因榜单重新出现而恢复STOPPED，不因已在库对象上榜而扩大用户未授权被动库范围。

## 4. 解析补丁开关的特殊影响

本插件托管质量和下载不影响未受管任务；但用户明确开启宿主Meta包装后，经过公共解析入口的其它流程也可能得到纠正。这一例外必须在界面说明并单独关闭。只允许两个函数，路径merge及直接MetaVideo覆盖不足要报告，不以这个开关授权改其它源码。

原文给的是方案，不是证明所有标题已经正确。CODE46/GATE24正则片段只作回归输入，完整输出需要当前V3解析器测试。Rust缺显式上下文时不覆盖用户指定的身份/季集；普通chat与AI提取不能在热补丁中调用。

## 5. 迁移切换事务

读取/导出并备份 → 解析/预演字段映射 → 新模块配置校验 → 导入原始历史及回执 → 用户确认停旧重叠调度/AI响应 → 开新模块 → 查询唯一处理者。

每一步保存MigrationReceipt、配置代次和操作身份；失败可续跑，不能再复制一个目标。迁移不自动删旧配置、不打印密钥、不重放clear/onlyonce/restore等按钮，不因新版插件名不同忽略旧STOPPED。

旧配置/历史访问只限用户授权实例。没有公开读取入口时支持离线导出，不直接读宿主ORM或要求用户公开token。回退先停新入口再恢复选定旧组件；新旧不同时写同一目标。

## 6. 验收与权限

每项功能对应主设计R51–R65及新增用例，原R01–R50不削减。策略条件和动作权限继续分开。没有测试授权时不在生产调用发现后自动订阅，不验证真实删媒体。此页的功能对照不代表功能已经实现或旧源无缺陷。
