# 当前版本、目标版本与进展的统一展示契约

## 一、事实归属

`GET /tasks/{id}` 的每个分集包含 `current_quality` 和独立 `processing`。前者来自可靠的在库档案，经原有质量规范化函数处理；后者只关联当前任务、当前拥有者、ACTIVE 计划/目标及相同目标代次、任务代次。旧计划晚到的进度不冒充当前升级。

计划创建时把实际参与比较的 `quality_facts` 写入不可变目标快照。展示字段包含分辨率、画面档、片源、高码率、音频档、特效字幕依据、发布组、平台和实测/声明来源。此补充不改变排序或准入规则。旧快照缺失就是未知，前端不解析文件名、不从排序分值倒推规格。

| 展示内容 | 数据来源 | 缺失处理 |
| --- | --- | --- |
| 当前版本 | 可靠且 PRESENT 的版本档案，最多 20 份 | 明示没有已确认质量；不推断可播放 |
| 目标规格 | 计划目标冻结的 quality_facts | 旧计划显示目标规格未记录；多视频目标不拼成一个伪版本 |
| 下载大小 | 当前目标选中文件及必要依赖的 saved progress | 缺少任一所需文件计数则保持 null，不拿整种子总量填充 |
| 采样时间/速度 | 同一批逐文件采样，跨时间取保守的最早时间 | 未取得；不生成百分比 |
| 跨集文件 | 文件目标集合大于一 | 明示包含跨集共用文件，不声称独占字节 |
| 秒传次数 | 交付包逐文件 confirmed misses | 未取得不填 0；旧包上限未记录不填配置当前值 |
| CD2 字节 | 本次本地发送记录 | 明示不代表云端已确认 |
| 必要附件 | 冻结依赖、本地归集状态、远端验证状态 | 只描述已记录范围 |
| 下次时间 | 当前文件真实 due | 无明确值显示尚未取得；过期值表示等待调度 |
| 外部结果未知 | 发布屏障、包和逐文件状态 | 优先显示先核对，不建议重复提交 |
| 演练/未启用 | 实际运行 health | 不把计划中的 due 说成必然执行 |

规范化函数用于比较的最低档默认值不是“已知规格”。未观测到的画面/音频最低档会在展示中恢复为未知。已声明与已测得的 SDR、DDP 等仍可正常显示。中文 PGS 推断不会标成明确特效字幕。

## 二、候选比较

列表继续去除大 evaluation 字段，另返回有界 `summary`：原因最多 512 字符，目标最多 8 项，每项最多 7 个比较维度，总目标数独立给出。没有把全量结果重新塞回列表。

点击展开才 GET 单条完整详情。读取失败保留重试；空记录单独说明；请求切换/卸载会失效旧响应。正文以每个目标的允许/拒绝/等待、原因和决定维度展示，25 个目标一页；每个目标正文最多 20 份版本比较。完整原始技术依据保留在折叠项。

## 三、最近计划

`/tasks/{id}/plans?sort=newest&limit=5&offset=0` 使用服务端 `created_at DESC,id DESC`，排序在 LIMIT/OFFSET 前。未传 sort 的审计调用仍按原先升序。候选业务列表也显式使用最新优先。历史计划的阶段标为“最后记录阶段”，不是新的执行承诺。

## 四、配置事务边界

连续方案入口复用整个配置草稿、已有组件和既有宿主保存流程。新建方案自动生成内部关联，用户输入业务名称、服务、分类和路径。五个步骤不是五次保存，不新增订阅接口。

“检查这份草稿”调用已有 preview，返回通过只适用于当时的完整草稿。编辑、切换、异步失败会让旧通过状态失效。最终仍通过底部“保存设置”提交。映射实测仅使用保存生效后的扫描记录，未保存修改不能复用旧成功。

AI 私密存储写入、配置保存、真实模型请求是三个独立阶段；界面分别显示，不合并成虚假的一次成功。
