# 用户应该怎样使用当前 UI

这是当前实现的操作说明，不代表每条业务链路都在本轮重新执行。默认不需要进入“高级诊断”。当前隔离实例普通执行关闭、演练开启；查看和测试读取不会自动变成真实下载。

## 1. 日常看一部作品

1. MP → 插件 → subscriBetter → 查看数据，默认进入“订阅”。
2. 输入片名，按需选状态、类型，点击“查找 / 刷新”。列表显示最近档案、当前处理和下一步。
3. 点击作品行，全宽显示详情，原列表暂时隐藏。
4. “分集与版本”中看三列：目标、最近在库记录、当前处理。1080p 在库与等待秒传的 2160p 文件可以同时显示，不能把等待中的文件当成已入库。
5. 超过 25 个已知目标，用“下页分集”。季、集在后端按数字排序后分页。
6. 看筛选理由用“候选比较”；查历史观察和计划用“处理记录”；仍有疑问才展开诊断依据。
7. 点击“返回列表”回到原筛选、分页与滚动位置，键盘焦点回到打开详情的作品。主导航换页表示换业务区，不等同于详情返回。

“已知 2 集”只表示当前确认了两个目标，不承诺整季共两集；缺少质量事实时显示未知。暂停不代表已经取消所有在途保护任务。

## 2. 添加或接管订阅

1. 新作品仍在 MP 原生搜索/媒体详情中创建订阅，沿用 MP 的身份和订阅接口。
2. 回到 subscriBetter 的“订阅”，点击“纳管已有订阅”。
3. 从原生订阅列表选择条目，核对片名、季和身份；配置缺少方案或授权时先补齐相应设置。
4. 阅读纳管预览及阻止原因，只有预览允许时才确认。前端提交原回执，不自行换 TMDb/豆瓣身份。
5. 返回订阅列表检查状态。自动接管仅按已保存的电影/电视剧选择与范围生效。

本轮没有通过这些步骤新建或纳管真实任务。

## 3. 首次配置服务与交付

1. 先在 MP 宿主配置下载器、媒体服务，以及已安装的 CD2/115 存储插件。
2. subscriBetter → 设置 → “基本设置与自动接管”。先看运行开关与演练模式，再选择要自动接管的新订阅类型。已有媒体升级使用“自动寻找更好版本的媒体库”的实际名称勾选。
3. “交付与映射”→ 云盘范围：从正确类型的插件实例中选择 CD2、115，填写 CD2 内部根目录和允许写入范围。不可用的已有实例会保留，不能因加载失败被清空。
4. 添加媒体库映射：选择 Emby 服务、真实媒体库与云盘范围，填写下表四个路径字段。已保存的映射名称是稳定引用，不在日常编辑中改名。
5. 添加交付规则：指定本地来源、云端暂存和整理入口，并单独检查字幕、交付与清理权限。
6. 回到“基本设置与自动接管”→ 下载与入库方案，选择分类、下载器、下载目录、交付规则。保存后的方案引用保持稳定。
7. 回到“交付与映射”，用“查看下载与入库方案”选择一个方案核对下载器、暂存、入口和关联媒体库。此处一次只展开一个方案，不把所有方案铺满首屏。
8. 点击“保存设置”，由服务端做引用/目录/权限预检，再交给 MP 保存。若只出现“已提交”，还不能当成保存完成；重新进入管理页核对应用回执。

| 路径字段 | 指哪一端 |
|---|---|
| Emby 中的 STRM 路径前缀 | Emby 容器返回的媒体路径 |
| MP 可以读取的 STRM 路径前缀 | MP 容器实际可读的 STRM 挂载路径 |
| STRM 内容中的播放路径前缀 | 打开 STRM 后里面记录的目标路径前缀 |
| CD2 内部文件路径前缀 | CD2 API 使用的云盘内部路径 |

长路径可以直接看、复制；“浏览 MP 目录”只对应 MP 的本地挂载，不会猜测 Emby 或 CD2 的目录。

## 4. 检查一条映射

1. 先保存映射。存在未保存的映射草稿时检查入口禁用，避免拿旧配置验证新输入。
2. 展开目标媒体库映射，再展开“用真实档案检查映射”。
3. 点击“读取此媒体库的扫描样本”，选择一个带时间的实际扫描记录；必要时翻页。
4. 从“真实作品”选择该扫描确实返回的条目，不填写内部扫描 ID 或路径。
5. 点击“检查这条映射”。成功会显示实际 Emby 路径、MP STRM 路径、转换出的 CD2 路径；失败保留错误供处理。
6. 没有扫描记录时，先在“扫描与恢复”配置范围并完成授权扫描，再回来检查。不要用手造 ID 代替样本。

该操作不上传、整理或删除文件；通过不等于 CD2 文件存在或能够播放。

## 5. 配置豆瓣榜单及测试抓取

1. “设置”→“榜单与 RSS”，填写自部署 RSSHub 地址与允许访问的私网范围。
2. 选择内置豆瓣榜单，或填写自定义路由/地址并选择电影/电视剧。仍兼容 `@@TV`、`@@Movie`。
3. 加入来源列表，检查启用状态、方案绑定和刷新计划；保存设置。
4. 回“发现”，默认看作品，按来源或处理结果筛选。
5. 展开“来源状态”，在需要检查的来源旁点“测试抓取”。结果就地显示条数或错误，不出现对象编辑表单。它不识别作品、不创建订阅。
6. “运行一次”会按规则识别，且可能创建或纳管订阅，是另一个动作；必须阅读它的预览和后果。“重新判定”也不保证订阅成功。

榜单重复出现的媒体复用缓存，新增豆瓣详情请求受已有间隔/去重与冷却约束。不要为 UI 展示更改这些后台规则。

## 6. 选择站点、质量与等待行为

1. “站点与搜索”：先勾选实际站点名称，再配置搜索方式；请求并发、结果上限等预算在高级区域。
2. 已保存但暂时加载不到的站点继续保留并标为不可用。先重试或检查宿主，不手填 ID。
3. “独立策略”：选择分类/策略，查看实际准入条件和排序优先级，修改后保存。当前库已有低于准入的新资源标准的旧版本，仍可以作为升级比较基线。
4. “观察、冷却、抢占”分三步：下载前是否等更好资源；在途是否允许替换；入库后是否暂缓升级。
5. 每轮替换次数 0 表示禁止。预算允许后，等待秒传/暂存与普通下载中的替换分别控制；普通下载还受进度与成本限制。
6. 时长输入旁可以选秒/分钟/小时/天；容量可选 B/KiB/MiB/GiB。切换单位只转换显示，不舍入原值；空值不自动变成 0。按字段说明检查必填项。
7. 秒传重试仍由独立时钟驱动；未知发布先核对结果，不能借“失败恢复”直接重复发布。

## 7. 配置 AI 名称辅助

1. “设置”→“AI 名称辅助”。这里仅辅助名称提取，没有聊天功能。
2. 填写服务地址、模型、适配方式与新密钥。已有地址不回显，留空可保留；新密钥默认追加到轮换末尾，替换整个列表需要显式勾选。
3. 点击“应用连接信息到草稿”：地址/密钥写到私密存储，草稿只接收自动生成的引用。不要去别页复制 secret 引用。
4. 如私密写入部分成功，界面保留已写成的引用和原有密钥，不假报整次成功。未完成输入时普通保存会被阻止；密钥失败后需重新输入，不能从页面取回明文。
5. 当前提示词在全宽区域编辑；“历史版本与恢复”只读查看备份，点击恢复才替换当前草稿。最后保存设置。
6. 若确实需要启用 AI，保存启用状态和连接后再点“测试已保存的模型连接”。该动作会使用固定影片标题并可能消耗少量额度，仍遵守缓存、轮换、冷却。
7. API 返回、缓存命中和未验证分别显示。名称解析预演只测本地规则，不能当成网络连通测试。

当前测试环境 AI 关闭，所以连接测试按钮禁用；本轮没有为截图临时打开 AI。

## 8. 处理交付异常与清理

1. 打开“传输与待处理”，按阶段筛选，点击交付行进入全宽详情。
2. 先看当前阶段、文件与必要附件、回执，再决定是否需要重试或重新核对。
3. “结果未知”先核对实际外部状态；“等待整理/入库”不等于上传失败；终态显示结束情况，不再给过去时间标“下一次检查”。
4. 需清理时先核对“清理权限”及该交付规则的对应权限。两层都允许才可能执行。
5. 读清理预览中的具体文件/范围与保留项，确认的是后端原始回执，不能在确认前编辑参数扩大范围。
6. 返回交付列表保留原位置。诊断仅在需要追查底层依据时进入。

本轮截图操作没有点击清理、取消、运行一次、立即收集或暂停等业务写入动作。

## 9. 窄屏、键盘与失败状态

- 窄屏配置使用“设置分组”选择器；保存栏固定，正文独立滚动。
- Tab 移动焦点，Enter 激活按钮或展开项；焦点外框保留。返回作品列表后可继续键盘浏览。
- 列表读取失败保留并标明旧数据；站点/媒体库加载失败保留已保存选择。不能把空列表和服务错误当成同一结果。
- 未保存编辑切换配置分组仍保留；“刷新当前值（丢弃未保存编辑）”会明确丢弃。关闭配置不等于保存。
- 本轮未做真实手机触摸、屏幕阅读器或全浏览器兼容性放行。
