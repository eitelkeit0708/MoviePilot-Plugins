# 用户到底应该怎样使用当前 UI

这是**按当前实现还原的操作路径**，不是理想版产品说明，也不是本轮把所有操作都执行成功的报告。普通用户如果必须长期依靠这份文档才知道下一步，说明界面本身还没有做好。

阅读约定：**已观察**表示本轮在真实 MP 页面打开并截图；**已执行**仅用于真实提交过的确定性策略预演；**代码预期**表示确认了当前实现，但本轮未提交该业务操作。实际保存、纳管、下载、对账和清理不能因为写在步骤中就计为验收通过。

所有图号可在[截图总览](SCREENSHOTS.md)找到。当前隔离实例是关闭追踪、开启演练的状态，这不是普通用户最终运行状态；本轮没有为了截图把它切成运行状态。

## 1. 先弄清三个入口

1. 在 MoviePilot 左侧进入 **插件 → 我的插件**，找到 subscriBetter 卡片，打开右下角菜单。图 50，已观察。
2. 选 **查看数据** 进入管理工作台，顶部有 **订阅、发现、传输与待处理、策略、设置**。图 01、07、10、13、15，已观察。
3. 卡片菜单的 **设置** 直接进入配置表单；也可以在工作台 **设置** 选择具体设置入口。配置左侧有 11 组。图 16–35，已观察。
4. 工作台右上角 **高级诊断** 是九个诊断域，面向排障和迁移；正常查看作品不应从这里开始。图 36–46，已观察。
5. 新增电影/电视剧仍使用 **MP 原生搜索和订阅**。插件工作台的“新增订阅使用 MoviePilot”是一句提示，不是完整的跳转向导；当前要关闭插件窗口回到宿主。图 01、50，已观察/源码核对。

**当前困难：**“查看数据”“管理工作台”“设置概览”“配置分组”“高级诊断”是不同层次，用户必须先记住它们。设置概览和配置分组还用了不同名字。

## 2. 首次配置：实际上必须跨页完成的顺序

适用目标：使用 MP 现有站点/下载器获取媒体，经 115/CD2 交付给 Symedia，并由 Emby 确认媒体库。只做部分功能时，不应强迫填写无关模块；但当前界面没有为不同目标提供准备向导。

下表是合理的依赖顺序，不是说保存任意一个未完成中间草稿都能通过校验。**同一个配置窗口可跨分组编辑，最后统一保存。离开窗口去高级诊断前，应先处理已完成的编辑。**

| 步骤 | 用户实际入口和动作 | 完成后应该看到/确认 | 本轮证据与障碍 |
|---|---|---|---|
| 1 | 在 MP 宿主配置站点、下载器、下载目录、Emby；在对应存储插件配置 CD2 与 115 | 各宿主服务本身可用，路径是对应容器能理解的路径 | 此前环境已配置；本轮未重新配置。插件只能引用已有服务，不能把已列出当作连通通过。 |
| 2 | 打开插件配置 → **基本设置与自动接管**，准备期间保持“启用订阅追踪”关闭、“演练模式”开启 | 模式条显示演练；普通下载交付不会启动 | 图 16，已观察。打开演练不是完整业务验收。 |
| 3 | **独立策略** → 为 MP 的电影/电视剧分类选择策略模板 | 对应分类出现绑定；能说明允许什么版本 | 图 19。分类由宿主提供，不能随便输入一个名字替代。 |
| 4 | 展开所用策略模板，填写允许分辨率、发布组/片源条件，调整比较维度顺序 | 规则值符合目标；理解修改共享模板会影响所有使用它的分类 | 图 20。共享模板与分类专属修改目前容易混淆。 |
| 5 | **交付与映射 → 云盘范围 → 添加云盘范围**，给范围命名，选择 CD2/115 服务，填写云盘根目录与允许写入前缀 | 一份限定云端范围的配置 | 图 25–26。选择器仍包含无关插件，不应据选项出现就认定其支持能力。 |
| 6 | 有 115 秒传父目录要求时，展开该范围高级配置，配置目标路径与 115 父目录标识的映射 | 云端父目录身份与路径匹配 | 此高级分支没有单独完整截图；源码 DeliverySettings/contract 可查。当前缺少云端目录选择器，这是需要技术介入的配置缺口，不能让用户猜 ID。 |
| 7 | **媒体库与两段映射**：选择 Emby 服务、真实媒体库和云盘范围；填写两段转换的四个前缀 | Emby 媒体路径能转成 MP 可读 STRM 路径，STRM 指向能转成 CD2 内部路径 | 图 27。四个路径属于不同命名空间，不能简单复制同一目录。 |
| 8 | 对 MP 本地路径使用旁边的目录选择器；仅选择当前容器可见目录 | 选中的目录回到草稿字段 | 图 47，目录读取已观察，没有实际选入。此选择器不代表能浏览 115/CD2 云盘目录。 |
| 9 | 检查媒体库扫描范围，保留需要扫描的真实库；如要被动寻找更好版本，回 **基本设置** 勾选相应库 | 扫描范围与被动升级授权分别符合目的 | 图 17、25。扫描范围不等于授权自动升级。 |
| 10 | **交付与映射 → 本地文件 → 115 → 整理入口 → 添加交付规则**；命名，选云盘范围，填本地监控目录、暂存目录、整理入口、消费者目标范围 | 下载落点、交付路径和整理后的预期位置有完整关系 | 图 28。现有测试布局使用 staging/incoming/media，不是其他用户必须照抄的路径。 |
| 11 | 若用于已有库版本升级，检查该组的档案分类策略绑定，与需要使用的分类策略一致 | 扫描出来的库媒体有可用策略 | 图 25及源码。不要以“订阅已绑策略”推定所有档案规则也自动完成。 |
| 12 | 回 **基本设置 → 下载与入库方案 → 添加方案**；填可读名称，选择 MP 分类、下载器、下载目录及前面建好的交付规则 | 一个可供纳管或榜单选择的完整方案 | 图 18。方案名称目前也承担配置引用，改名不能当纯装饰操作。 |
| 13 | 按需要处理 **站点与搜索**、**生命周期**、**观察/冷却/抢占** | 用户知道搜索范围、追踪时限、等待多久以及继承值 | 图 21–24。站点仍是 ID，继承最终值不展示；没有可靠的人类选择流程时，应登记未完成，而不是猜值。 |
| 14 | 检查 **扫描与恢复** 和 **安全与容量** | 确定扫描周期、恢复验证和容量边界 | 图 29、31。原始秒数/字节和恢复引用难理解。 |
| 15 | **清理权限** 只打开需要的项目，并在交付规则内授予对应权限 | 清楚区分删本地、删云端暂存、移除下载器记录、删除下载器数据 | 图 30、28。两层授权必须同时满足；本轮未打开任何删除权限。 |
| 16 | 如果需要榜单，完成下一节的 RSSHub/来源/方案绑定；需要 AI 时按第 8 节单独配置 | 功能开关、来源和服务有完整绑定 | 图 32–35、44、48–49。两者均不应是普通手工订阅的强制步骤。 |
| 17 | 点击底部 **保存设置**；若预检指出关联/路径问题，留在配置中修正后再提交 | 先通过配置预检，再交给宿主保存 | 图 16–35仅显示入口；保存过程为代码预期，本轮未执行。 |
| 18 | 重新打开 **查看数据**，必要时点 **刷新** | 明确看到“设置已保存并确认生效”；未确认时仍按旧的实际配置看待 | status.mjs/client.mjs 代码预期。关闭窗口或“已提交给 MoviePilot”不等于生效。 |
| 19 | 到 **高级诊断 → 版本档案 → 测试两段映射**，按实际对象验证映射；核对服务和消费者恢复结果 | 逐段得到真实读取结果，未验证的能力继续标为未验证 | 图 38只覆盖入口；本轮未运行映射测试。当前与配置跨页，尚不适合无技术指导的首次使用。 |
| 20 | 准备实际运行时，回 **基本设置** 启用追踪、退出演练，保存并回读；如存在旧插件功能重叠，先按第 9 节完成唯一处理者核对 | 顶部反映实际运行，且没有重叠处理者或阻断原因 | 本轮未执行。不能只依据开关打勾就宣称开始运行。 |

**怎样才算完成：** 配置回读生效，实际对象映射验证成功，用户能解释一部作品使用哪个策略、下载到哪里、交给谁整理。当前 UI 没有把这 20 步组织成连贯流程，因此首次配置评为严重摩擦。

## 3. 豆瓣榜单：使用自己的 RSSHub

1. 配置 → **榜单与 RSS**，填写自部署 RSSHub 容器地址。本环境是 `http://192.168.50.6:1200`；这是当前测试服务，不是公共路由。图 32。
2. 在“允许访问的内网范围”填写对应服务的必要范围；本环境是该地址的 `/32`。不要为省事扩大成整个内网。图 32。
3. 设置刷新计划与豆瓣详情读取间隔。当前显示 5 秒；同媒体缓存复用与新增详情读取间隔是两件事。此处不是让用户为每次刷新重新查全榜。图 32。
4. 在“添加榜单”选择内置豆瓣榜单，或把来源方式切到 **自定义地址 / 路由**。图 32、49。
5. 自定义路径可填 `/douban/list/tv_real_time_hotest@@TV`，电影可填 `/douban/list/movie_real_time_hotest@@Movie`；也支持完整 RSSHub 地址。`@@` 后是类型提示。这里只说明当前输入方式，不表示本轮再次抓取了这些地址。图 49。
6. 点击 **加入来源列表** 后展开新来源，改成能区分的名称，核对媒体类型、启用状态、最低年份/评分以及电影、电视剧、动漫对应方案。图 33；添加与保存为代码预期，本轮未提交。
7. 如需额外季范围、现有媒体处理、请求预算或代理，展开高级选项；普通用户不应为了添加一个榜单先编辑任意对象。
8. 启用榜单发现及需要的具体来源，按第 2 节的保存/回读步骤确认；是否真正运行还受总启用、演练及唯一处理者限制。
9. 返回工作台 **发现**：默认先看发现作品；通过来源筛选定位。展开来源区可看来源状态。图 07–08，已观察。
10. 点某来源 **测试抓取**。期望仅抓取、不识别/提交；当前弹窗仍显示 `source` 对象编辑。图 09，仅打开未执行。这一步不能说普通用户已经可以顺畅完成，需要 UI 修正或明确业务输入。
11. 真正希望运行该来源时，使用对应运行入口，核对范围后确认；回到作品列表检查识别、策略和提交结果。此步骤为代码预期，本轮没有触发外部请求。
12. 来源设置变更导致历史需重判时，使用对应历史的重新判定动作并核对结果；不要把“来源抓取成功”当成“每部作品已订阅”。关联任务入口目前可能落到高级表格，仍有体验断层。

**当前困难：** 添加来源需要先有完整下载方案；命名、策略绑定和抓取测试仍不够直接。发现页已经把作品放在来源前面，这是实际改善，但不是流程整体通过。

## 4. 用户主动订阅一部作品

1. 关闭插件窗口，在 MP 原生搜索框搜索作品，核实年份、媒体身份、电视剧季及分集组，然后按原生流程添加订阅。图 50展示宿主入口；本轮未新增作品。
2. 如果已经开启了相应类型的 **自动接管新订阅**，保存配置生效后，符合范围的新订阅可进入自动接管流程。用户仍需到插件订阅列表核实结果，不能只看到原生订阅创建就认定接管成功。
3. 如果要显式纳管一个已有订阅，打开插件 **订阅 → 纳管已有订阅**。图 05，已观察。
4. 在原生订阅分页列表中找到并选择作品；电视剧核对季。当前没有作品搜索，也没有完整已纳管标记，切勿因为列表还出现就重复操作。图 05–06。
5. 在确认页选择预先配置的 **下载与入库方案**。没有方案必须返回设置完成，当前不能在确认页直接补齐。图 06。
6. 阅读执行权变化：原生订阅暂停执行，由插件筛选、升级和交付，原订阅记录与下载任务保留。确认符合意图后点 **确认纳管**。当前实例演练中，此按钮不可提交；本轮只观察到这里。
7. 提交后刷新插件订阅列表和 MP 原生订阅，确认媒体身份、季/分集组、方案以及管理状态。源码会在提交前重读原生记录；若身份变化或结果不明确，先核对实际状态，不能反复点击。此为代码预期，未做新纳管验收。

**不应该要求用户做的事：** 在插件另建媒体搜索/创建接口、手填 TMDb/豆瓣身份替代原生确认、直接调 API 完成人类常用操作。

## 5. 每天查看进度、暂停、恢复与交还 MP

1. 打开 **订阅**，通过名称、状态、电影/电视剧筛选，点 **查找 / 刷新**。图 01。
2. 看一行中的作品、最近档案与版本、当前处理、下一步。这里的“最近档案”不是已播放，也不自动等于完整收藏；“版本信息待确认”应如实当未知。图 01。
3. 选中作品进入详情，查看分集、已有版本、观察期限和候选依据。图 02–03。当前集数顺序和双列密度有缺陷，不能要求用户适应异常排序。
4. 需要暂停时点 **暂停追踪**，阅读确认说明后提交。图 04只打开确认框，未暂停。此操作不是删除已有媒体。
5. 恢复时使用对应恢复入口；如果提示仍有在途计划、未知结果或原生状态不一致，先核对这些对象。不能通过重复恢复绕过保护；恢复也不应重置原来的观察时间/失败预算。此为代码预期，未执行。
6. 想回到原生 MP 管理时，在详情下方使用 **交还 MoviePilot**，先看预览是否允许及具体对象，再确认。不能将“停止追踪”与“已交还 MP”混为一谈。图 03含入口，未提交交还。
7. 单集即时检查只在有相应机会/对象时使用；它不等于强制下载，也不跳过准入、归属或权限。当前日常页面不能解释清楚时，高级依据可排障，但不应成为用户每次必经之路。
8. 如果顶部仍是演练模式，等待/追踪标签不代表普通下载正在执行。先看模式和当前原因，再判断作品是否卡住。

**完成信号：** 用户能说清某集当前有什么、等待谁、何时/如何继续。当前部分占位解释没有达到这一点。

## 6. 调整质量策略并理解为什么选这个版本

1. 工作台 **策略**，左侧选择分类。图 13。
2. 先看“收录条件”，再看优先顺序。准入是能否进入比较；优先顺序是在准入后的资源之间比较。不要把“1080p 出现在排序说明”理解为当前分类必定允许 1080p。
3. 点 **编辑策略** 进入配置 **独立策略**；核对该分类绑定的模板。图 19。
4. 调整允许分辨率、片源/发布组、比较维度，必要时看额外锁定。修改共享模板会影响其他绑定分类；当前 UI 对全局与分类影响仍需强化。图 20。
5. 保存并回读确认后返回策略页。预演读取**已保存策略**，不是尚未保存草稿。配置保存本轮未执行。
6. 在“用真实候选预演”选择分类和已有候选；可选对照资源。没有候选时，正常搜索积累后再用，不能凭空宣称已经实测。图 14。
7. 点击 **预演当前策略**。本轮确实执行过一次，得到拒绝结果；没有启动下载，也不证明真实下载链路通过。图 14。
8. 看结果与原因，必要时展开完整比较依据。当前泛化理由与原始比较结构仍占主导，用户不容易知道具体是哪个条件拒绝；应修为“资源值 vs 规则值”的解释，而不是让用户读向量。

## 7. 处理上传、Symedia 整理、Emby 确认问题

1. 工作台 **传输与待处理**，按处理阶段筛选目标。图 10。
2. 打开作品，核对文件组、当前阶段和文字说明。文件已交付与整理/媒体库确认是不同状态；历史“下一次检查”时间不能自动当成仍在调度。图 11。
3. 遇到 **结果未知/发布待核实**，点 **核对实际状态**。图 12为打开后的核对框。第一次“核对操作”只是准备本次操作，不应误认为已经查询远端完成。
4. 读完对象、阶段和后果后，才确认真正的对账请求；返回列表刷新结果。本轮未执行最终确认，不能宣称 UNKNOWN 已解决。
5. 对可重试的已知阶段，点 **继续处理**：上传阶段重试传输，远端已核实后重试发布，等待消费者时核对消费者阶段。具体按钮由当前状态决定，不需要用户自行输入任意阶段。但实际是否获准仍由服务端重新检查。
6. Symedia 已交付文件的补扫/恢复能力在项目中已得到用户说明；当前 UI 仍要展示本对象是否被整理、媒体库是否确认，不能仅写“支持补扫”就算此对象完成。Symedia 为共享单容器授权，不新增第二个实例。
7. 如果决定放弃，使用 **取消交付** 并核对预览。取消保留下载器任务和数据；未知结果或共享引用可能阻止取消。本轮未执行取消。
8. 若另需清理，展开 **外部回执与安全清理 → 预览可清理对象**，逐项核对位置、文件、保留对象和权限后再确认。没有权限不能把启用所有清理开关当作排障默认动作。本轮没有生成新的清理预览或删除数据。
9. 无法解释的对象再进高级交付/健康域查看外部 ID、原始操作和扫描记录；应把得到的结论带回作品页，而不是日常让用户在 Hash 与 ID 间追踪。

**完成信号：** 交付阶段有明确结果；需要入库时另有消费者及媒体库确认。截图中的旧 UNKNOWN 和历史附件只是当前显示证据，不是新验收结果。

## 8. AI 只用于辅助名称识别

不需要配置 Telegram、微信或独立聊天。聊天功能已不在该流程内；本插件 AI 的任务是辅助识别，不能把它当订阅控制聊天机器人。

1. 先决定是否需要 AI。无需 AI 时，不为完成下载/入库而被迫填写模型设置。
2. 需要连接时，当前 UI 要先到 **高级诊断** 展开 **私密凭据写入 / 轮换**。图 44为空表单，未输入密钥。
3. 类型选择 **AI 端点**，输入已授权的服务端点，点 **写入并清空输入**；保存返回的私密引用。然后选择 **AI 密钥** 重复一次。此为代码预期，本轮未写入或轮换凭据。
4. 返回配置 **AI 名称辅助**，把端点引用和密钥引用填到对应字段/引用列表，选择实际模型名称。当前列表仍是通用数组编辑，不是连接选择器。图 34、48。
5. 检查启用项、请求预算、超时与缓存等配置；内部名称辅助和宿主 NameRecognize 桥接影响范围不同。启用公共解析入口影响其他经该入口的流程，不能理解成只影响当前作品。
6. 提示词与备用模型只在确有需要时编辑。当前大段提示词输入区偏小且备用字段同等突出，不适合普通用户第一次配置。图 35。
7. 保存并回读；涉及旧 AI 模块重复处理时，按第 9 节唯一处理者流程处理，不只是同时打开两套开关。
8. 名称含数字保护在 **基本设置 → 名称识别**，可把如 `GATE24 The Border` 的完整目标片名作为保护规则输入，回车添加。应使用实际需要保护的完整片名，不能把字幕里数字都当噪声。图 17。
9. 高级 **解析与 AI** 可查看样例和确定性差异；实际模型网络调用与确定性解析不是同一测试。图 43。本轮没有新的模型调用，所以不提供“DeepSeek 连接验证通过”的结论。

**当前困难：** 用户在第 3–4 步要搬运 opaque reference；服务端私密存储是正确机制，但把引用管理交给用户不是合格体验。应将连接配置收进 AI 页面，而不是删掉安全存储。

## 9. 旧插件迁移：只给确实需要迁移的管理员

这不是每次安装都要走的向导。存在旧功能重叠时，唯一处理者核对也不能被忽略。图 45–46只展示入口与展开表单，没有迁移成功状态截图。

1. 先备份旧配置和历史；新实例准备配置并保持关闭/演练，不重放旧一次性按钮。
2. 高级诊断 → **整合迁移**。离线导入时选择明确授权的 JSON 导出，填写来源实例/版本/时区，文件最多 2 MiB。
3. 点 **逐字段与历史预览**，阅读配置和历史映射；只有预览对象正确才明确确认下一页导入。每次导入有上限，旧成功历史不代表新系统真实媒体已存在。
4. 从旧榜单服务读取时，先写入授权旧服务地址/凭据的私密引用，再选择 **预览只读来源**，核对预览出的读取范围后才执行。此处没有外部旧服务已停机的自动保证。
5. 需要切换处理者时，展开 **当前宿主唯一处理者切换**，读取宿主实例与摘要，选择期望开启的新功能和精确的旧功能范围。
6. 执行 **预检最终配置并预览切换**；核对旧实例变更，只对回执指定对象进行保存。原始摘要不一致时先刷新，不能用新猜测覆盖。
7. 回执 READY_CONFIG 只代表可以提交绑定配置。进入配置加载该回执并保存，返回迁移回执再做 **核对 / 激活**；ACTIVE 才表示该流程确认了当前宿主新模块唯一处理者。
8. 需要回退时使用对应回退流程并核对步骤，不能直接重启所有旧开关。结果未知时读取原回执继续，不另造一个等价操作。

上述全部是源码预期，本轮未导入、切换或回退。当前通用表格和回执结构适合维护者，不足以称为人类友好的迁移向导。

## 10. 保存、错误和禁用按钮该如何理解

| 页面信号 | 正确理解 | 不应作出的判断 |
|---|---|---|
| 已提交给 MoviePilot，尚未确认生效 | 需要重开管理页回读 | 弹窗关闭了，所以保存成功 |
| 设置已保存并确认生效 | 当前配置与对应回执匹配 | 所有远端服务/下载/入库都验证了 |
| 演练模式 | 普通下载交付不执行，任务保护独立 | 任务标签追踪中就一定在下载 |
| 尚未取得媒体库确认 | 状态未知或未完成确认 | 必然失败，立刻重传 |
| 列表读取报错，保留旧数据 | 正在看上次结果，操作受限制 | 屏幕有一行记录所以它是最新状态 |
| 纳管不可提交 | 检查总启用、演练、当前状态、方案选择 | 用高级接口绕过 UI 保护 |
| 来源测试打开后仍要求 source 对象 | 当前 UI 存在业务表达缺陷 | 普通用户必须懂 schema 才算会使用 |

完整的“保存成功/冲突/失败/失联/未保存离开”交互仍需要实机专项验证。本轮没有凭空生成这些状态的截图，也没有把代码防护存在等同于交互已经好用。

## 11. 每类用户的最短日常路线

- **手工订阅用户：** 宿主原生创建 → 插件选择已有订阅和方案 → 核对接管 → 看作品/季集 → 按真实原因处理。首次配置完成后，不应再接触内部 ID。
- **豆瓣榜单用户：** 设置 RSSHub 和榜单 → 绑定方案并保存 → 发现页看作品与处理结果 → 异常时看具体来源。不能把“抓取测试”做成对象编辑器。
- **已有库升级用户：** 授权媒体库 → 完成映射、策略与交付范围 → 核对扫描 → 看版本变化。扫描与升级权限必须能区分。
- **日常维护者：** 订阅看当前状态 → 传输看交付阶段 → 对未知结果对账 → 仅在需要时进高级诊断。不能要求每次理解回执代次和原始 Hash。

这些是当前实现试图支持的用户任务。前面的冗长路径、跨页依赖和明确卡点就是待修复对象；不能用这份操作手册替代产品改进。
