# subscriBetter 新 UI：真实宿主截图与待审计包

**结论：当前版本不应按“普通用户可独立使用”放行。** 五个业务页已经存在，一部分常用设置换成了专用控件；但首次配置、异常处理和 AI 配置仍要求用户理解内部对象、引用和回执。视觉密度、导航命名、状态解释也没有形成完整一致的体系。本文件是开发方自审和外部审计输入，不是独立审计通过证明。

本轮仅取证、阅读源码、编写文档，没有修改产品代码、保存配置或启动下载。此前“界面验收候选”表示可以检查，不表示视觉和可用性通过。本报告补充真实截图后，对放行条件作出更明确判断。

“存在摩擦”指当前任务仍可理解但费力；“严重摩擦”指普通用户很容易中断或误解。这里评的是体验，不是 API 可用率。

## 缺陷台账

优先级：P1 阻碍日常独立使用或容易形成错误判断；P2 明显增加认知、阅读、操作成本。未把没有执行过的写入、下载或清理宣称为故障。

| ID | 级别 | 观察证据 | 用户影响与修复验收条件 |
|---|---|---|---|
| U01 | P1 | 15–33：首次准备横跨分类、映射、交付规则、下载方案、来源绑定；没有依赖状态 | 新用户不知道先填什么。应从真实配置生成待办顺序，缺项直达对应设置，并能返回继续；不靠本文作为产品导航。 |
| U02 | P1 | 02、03：打开详情后左列缩成高窄条目，详情长页下方左侧大量空白 | 用户不能稳定比较和定位作品。主列表与详情应有明确分工，详情展开后也必须保持可读宽度和单一主要滚动路径。 |
| U03 | P1 | 02 首行从第 10 集开始；补充 DOM 证据显示一瓯春顺序为 10…19、1、20…29、2、30、3、4 | 不符合逐集阅读习惯。应按季/集的数值顺序展示，并验证跨分页边界；本报告只认定观察到的排序问题，未将字符串排序猜测当成已定位根因。 |
| U04 | P1 | 01–03、14：部分条目是“版本信息待确认”“需要查看详情确认处理条件”，停止状态在当前/下一步重复 | 缺少“等待什么、是否会自动继续、用户该做什么”。未知保持未知，但要给出可追溯的原因和下一行动；不能改成虚假的失败或成功。 |
| U05 | P1 | 09：已在具体来源上打开测试，却要求编辑 source 对象 | 常用操作泄漏请求结构。默认应带入当前来源，直接展示名称、地址、类型和请求范围；高级覆盖另放。仅打开未提交，因此没有认定该请求必然失败。 |
| U06 | P1 | 22、23：授权站点显示数字 1，外层 entry/添加项 | 人类需要猜 MP 内部站点 ID。应按宿主真实站点名选择；无法加载时保留原选择并明确报错，不要求用户手填 ID。 |
| U07 | P1 | 24：大量“未设置/使用该字段的继承语义” | 无法判断实际等待周期。每个可继承项需给出当前有效值、来源和恢复继承的行为。 |
| U08 | P1 | 27–29：四段路径映射、短输入框、验证入口位于高级档案；恢复页要求引用 | 目录配置错误难以发现。应在表单旁逐步验证一个真实样本，分别展示 Emby→MP STRM→CD2 的结果；恢复能力不能只靠粘贴内部引用解释。 |
| U09 | P1 | 34、44、48：AI 端点和密钥先写私密存储，再返回设置搬运引用 | 一个配置任务分散到两套导航和表单。应在 AI 配置内完成连接设置并显示连通/模型状态，保留服务端私密存储；不把密钥放回普通配置。 |
| U10 | P1 | 10：历史交付条目“下一次检查”显示早于本次取证的日期 | 容易误以为调度失效或仍会执行。区分计划时间、上次尝试、暂停/演练期间不调度；终态不展示未来行动承诺。未据此认定后台调度故障。 |
| U11 | P2 | 05–06：可选择一瓯春等已在管理列表的对象；没有已纳管标签 | 需要用户记忆状态。列表应显示可纳管/已纳管/不可纳管原因并提供作品搜索。演练时禁用提交是正确保护。 |
| U12 | P2 | 08：多个“自定义榜单”，重复周榜名称和历史来源 | 筛选与运行容易选错。首次添加就给出可读名称；冲突时以类型/站点辅助区分，地址放详情。 |

| U16 | P2 | 18、20、26–35：原生 VBtn、普通输入/选择器、Field 数组混用 | 行高、焦点、按钮语义和空白不统一。定义组件规格并在所有常用表单一致使用；不靠再加一层卡片。 |
| U17 | P2 | 21、31 对比 27、35：简单页大面积空白，复杂路径/提示词区域狭窄 | 空间不随任务复杂度分配。路径能读完整关键部分；大段提示词应有合适的编辑高度，高级字段渐进展开。 |
| U18 | P2 | 26：存储插件选择器可见无关的已安装插件 | 选择范围缺少能力筛选。按所需 CD2/115 能力筛选，不把后台拒绝当主要用户引导。 |
| U19 | P2 | 11、12：长目录与内部证据占主要空间，动作经过通用“核对操作” | 用户难分清查看与真正发起对账。先展示作品、阶段、最后结果与后果；确认区明确尚未提交/已提交/结果未知。 |
| U20 | P2 | 30、28：全局清理权限和规则授权分开 | 安全边界应保留，但操作处需要汇总当前是否允许及缺少哪层授权，避免跨页猜测。 |
| U21 | P2 | 31：容量显示 1073741824 等字节数 | 需要心算。默认可读单位，必要时查看精确字节，保存值不丢精度。 |
| U22 | P2 | 36–43：档案目标、内部 ID/Hash、泛型对象直接铺开 | 高级工具可保留，但日常流程不应依赖它完成解释；档案行至少携带作品名、季集和版本摘要。 |
| U23 | P2 | Config.vue：关闭/返回直接 emit，未见未保存草稿确认；本轮只切换未提交的来源模式 | 有丢失编辑风险。需要单独有真实修改的回归验证；本轮未制造或宣称实际数据丢失。 |
| U24 | P2 | 16–49：切换配置组不显式复位内容滚动；截图可能落在中段 | 用户可能看不到新分组标题。应明确每组滚动恢复策略并验证鼠标/键盘；本轮语义按键切换成功，不声称鼠标菜单故障已修复。 |

## 视觉与可访问性复核

- 已改善：正文使用相对稳定的深色表面；列表确有作品/版本/处理/下一步四列；状态条简化；媒体库能显示真实名称；两个媒体类型、片名标签、清理权限已有专用控件；保存栏可见。见 01、16、17、30。
- 未解决：正文与辅助信息字号差、低亮度紫色文字、普通 HTML 控件与宿主组件的尺寸差异、长表单阅读疲劳。见 23、27、35。属于可见风险，没有测量出对比度比值，不能宣称符合或不符合某一 WCAG 数值条款。
- 本轮能用语义定位和 Enter 切换菜单、展开控件，但这不等于完整键盘可用性：焦点陷阱、ESC、关闭后焦点返回、只用 Tab 的顺序均待专项检查。
- 背景模糊仍可在宿主层看见；本报告不建议全局改 MP 主题，也不把宿主效果全部归罪于插件。应验证插件正文在不同宿主主题下的可读性。
- 当前含内部测试名称不能直接证明生产业务设计错误；但 UI 必须在名称重复、过长、缺失和历史状态下仍能帮助判断，不依赖“理想数据”。

## 需要保留的机制

原生 MP 搜索和新增订阅入口、宿主服务引用、演练/启用边界、私密存储、配置预检与生效回读、未知结果先对账、清理精确预览、全局/规则双层删除权限都应保留。改善界面不是删除这些保护，而是由系统把范围和后果解释清楚。
