## 入口与执行边界

人类用户在 MoviePilot 原生界面搜索和新增订阅。插件只提供已有订阅的显式纳管，提交前重读媒体来源、媒体 ID、季和分集组；不另建媒体搜索或订阅创建接口。自动榜单发现仍使用原有内部意图接口和原生 SubscribeChain。

已纳管订阅暂停原生执行，由插件负责优选和交付。界面明确告知这一点。已停止任务保持终态；暂停任务使用新增的、校验任务代次的恢复接口，重新核实原生订阅身份和暂停状态。存在未收束计划或未知发布结果时拒绝恢复，需先对账；不会通过恢复操作重置原观察期限和失败预算。

## 主要变化

- 五个业务页面：订阅、发现、传输与待处理、策略、设置。原有九域数据浏览器保留为高级诊断。
- 作品名称、分集质量、观察期限、候选比较、单集检查、交还原生管理；交付列表显示作品名，区分文件交付和消费者确认。
- 使用宿主已有下载器、Emby 服务及媒体库；MP 本地目录浏览使用原生只读 `storage/list`。云盘路径可手工填写；115 父目录映射仍是高级手工配置，不声称已实现云盘目录树。
- 自部署 RSSHub、内置豆瓣榜单、自定义路径及 `@@TV` / `@@Movie`；每个来源可有限测试抓取和运行。
- 分类策略绑定、准入、维度上移/下移、显式锁定；后端比较和策略版本同步使用配置模板。预演使用当前已保存策略和已有真实候选，不声称是在比较未保存草稿。
- 完整配置保存采用替换语义，删除项能持久化；保留旧局部合并调用。草稿绑定自身版本，刷新期间禁止保存，避免覆盖别人新配置。只有回读到匹配且 APPLIED 的回执才显示生效。
- 清理确认直接展示删除位置、文件与保留范围。管理员确认接口按白名单投影必要路径，不导出完整计划、凭据或传输上下文；执行仍校验原不可变回执及权限。

## 复现

```powershell
npm --prefix plugins.v3/subscribetter/frontend ci
npm --prefix plugins.v3/subscribetter/frontend test
npm --prefix plugins.v3/subscribetter/frontend run build
```
