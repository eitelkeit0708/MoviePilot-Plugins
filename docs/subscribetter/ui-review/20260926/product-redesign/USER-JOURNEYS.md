# 用户应该怎样使用

下面描述最终实现的操作，不表示每条真实业务链路都已在本轮重新执行。真实、合成与未测范围见 VALIDATION.md。插件入口为 MoviePilot → 插件 → subscriBetter。

## 1. 第一次配置一套下载与入库方案

前置：在 MoviePilot 配置下载器、Emby、CloudDrive2 储存、115 储存，建立分类；在 Symedia 配好真实监控入口和整理规则。插件选择这些现有服务，不在这里建立另一套账号或媒体搜索服务。四种路径来自实际部署：不是随便填写相同的目录。

1. 管理页 → 设置 → 下载与入库方案。输入人类可读名称，点「新建方案」。程序自动创建内部关联，不要求填写规则或映射 ID。
2. **下载与分类**：选 MoviePilot 分类、下载器、下载目录及收录与升级策略。点「继续」。缺项在当前步骤显示，点击错误定位控件；也可以返回上一步。
3. **云盘与写入范围**：选已安装的 CD2 和 115 实例；填 CD2 内部根目录与允许写入目录。目录必须处于声明根目录内。若当前 115 接入需要父目录编号，在高级「115 父目录映射」维护，这是外部 115 文件夹标识，尚未提供自动选取功能；不能把它描述成任何环境都无需编号。
4. **媒体库与播放路径**：选 Emby 服务和实际媒体库名称；填写 Emby 中的 STRM 前缀、MP 可读取的 STRM 前缀、STRM 内容中的播放前缀、CD2 内部文件前缀；选库内比较策略。已有共用云盘可能关联多个媒体库，每份分别显示名称。不能依据剧集方案名称自动推定唯一映射。
5. **暂存与整理**：填 MP 监控的本地文件目录、115 暂存目录、Symedia 入口及它实际监控的目录。暂存必须处于监控范围外。按需启用整理规则。高级选项保留普通上传、通知、稳定等待与各项清理权限；默认不代替用户授权删除。
6. **检查并保存**：核对目录、运行方式、共享修改影响和「本次保存范围」。这是整份插件配置保存，列出的其他未保存组也会提交。点击一次「保存方案」；程序顺序预检、原生保存、回读，不需要搬运回执。
7. 显示「已保存」仅表示配置生效。点「检查播放路径」回到第 3 步，在对应媒体库展开实际样本检查。
8. 点击「读取此媒体库的扫描样本」，选择真实扫描与作品，再点「检查播放路径」。通过只说明该样本 STRM 的路径转换；不等于云端齐套、播放测试或实际入库成功。
9. 无样本时，在同一处打开「查看扫描与恢复设置」。标题显示刚才选择的媒体库；选择自动扫描并调整间隔。全局启用/演练开关影响全部方案，必须按实际运行意图决定。保存后等待真实扫描记录，再读取样本。

**退出/失败**：返回工作台或关闭时，未保存内容会出现离开保护，可保留草稿再离开。相同有效配置基线下刷新可恢复浏览器草稿；不恢复原始密钥输入。服务端基线改变时不能拿旧草稿覆盖新配置。预检失败保留输入，返回相应步骤修正。原生保存响应丢失时先「核对保存结果」，不要重复提交。

**名称限制**：现有模型把方案名称同时当稳定标识。新建时可命名；已保存方案没有伪装成安全重命名的入口，本轮没有执行 ID 迁移。

## 2. 添加与接管订阅

1. 仍在 MoviePilot 原生搜索/媒体详情添加订阅；这里没有第二个搜片与身份创建接口。
2. 若已配置自动接管类型与方案，符合条件的新订阅进入原有接管流程。否则在插件「订阅」点「接管已有订阅」。
3. 选择宿主已有订阅和下载与入库方案，核对标题、类型、季等既有身份，再确认接管。
4. 接管改变原生执行权；不要把接管理解为简单加一个界面标签。具体冲突与所有权由后台校验，发生冲突在对应诊断入口处理。

## 3. 每天查看作品和分集

1. 「订阅」列表先读当前处理与下一步。可以按作品名、状态、类型筛选。暂停、停止、待核对不能当成下载故障。
2. 点作品进入全宽详情。「分集与版本」每行展示库内版本、本轮升级和进展。没有在途计划时不把旧入库记录冒充本轮升级完成。
3. 例：1080p · SDR · 普通音轨 → 2160p · Dolby Vision · DDP，说明已有证据中的质量差别；「发布者标注」不等于实测。普通音轨档位不能推出 AAC 编码。
4. 下载有可靠已完成/总字节才显示进度条；秒传只显示有效未命中次数。`2 / 6` 表示累计 2 次、阈值 6 次，不是还可重试 6 次。到期时间来自服务端，演练/暂停时不承诺会执行。
5. 点该集「详情」看各版本、文件、字幕、跨集共享、绝对时间与档案入口。多个视频规格不拼成一个虚构版本。
6. 「作品操作」可以暂停追踪、恢复、刷新或交还 MP。暂停不等于暂停下载；取消不等于删除文件。出现确认和限制时按具体范围核对。
7. 返回列表恢复原筛选、滚动和焦点。本轮真实记录为 827.5 → 827.5 像素；不能扩大为所有屏幕和触屏手势都已验证。

## 4. 为什么这个候选被选择或拒绝

作品 →「候选比较」。先看结论、主要理由、决定性比较项和集号范围。相同原因汇总，不同原因分行。若显示「8 / 16」，只代表本次摘要的 8 条结果。点「查看本次比较依据」才请求单条完整决策；加载中、读取失败、没保存依据分别显示。失败可重新读取，不能把错误当作空历史。原始技术依据位于最内层，日常比较不要求读 JSON。

## 5. 发现与榜单

「发现」先看作品及处理结果，来源和结果作为筛选。异常来源以短提示出现，展开来源状态再看详情。点「管理来源」到榜单设置：填写自部署 RSSHub 地址、选择豆瓣榜单或自定义路由及类型，保存；已保存来源可原位试读。路径与内部 key 是详情，不要求用户按公开 RSSHub 服务配置。重新判定已有作品需要明确点击，不因浏览页面而自动发起写操作。

## 6. 处理传输异常

「传输」按阶段筛选，点文件组看具体文件和字幕。结果未知先「核对实际状态」；已有外部请求不能因页面超时就重新上传。普通阶段的「继续处理」仍受服务端权限、预算和状态限制。正在取消时等待本地读取和外部操作核实结束。取消交付保留数据，删除另走「外部回执与安全清理」→ 精确预览 → 确认，并受独立权限控制。本轮没有执行这些生产副作用。

## 7. 调整质量策略

「策略」选择分类，读取实际保存的收录条件、比较顺序和锁定条件。用已有候选预演只比较，不下载；编辑策略回到对应配置。分类绑定与库内档案绑定仍是原有独立关系，界面不偷偷合并语义。

## 8. 配置 AI 名称辅助

1. 设置 → AI 名称辅助。填服务地址、模型、适配方式和新密钥。
2. 点「保存连接与设置」。先写私密信息，再预检、保存普通引用并回读；显示本次同时保存的其他改动组。
3. 私密写入部分成功时保留已写入引用，显示未完成；不是一个跨私密存储和配置的原子事务。不要把「写入」等同「测试成功」。
4. 连接配置生效后点「测试连接」。固定标题会发送到已配置模型并可能消耗额度；不自动开启生产 AI。
5. 需要生产识别时才自行启用名称辅助并保存。提示词、历史恢复、轮换顺序、范围、缓存与预算仍有入口。原始地址和密钥不回显。

## 9. 全局维护入口

| 设置组 | 用途 |
|---|---|
| 基本设置与自动接管 | 启用、演练、接管类型、受保护名称、下载方案维护 |
| 独立策略 | 分类与质量规则 |
| 自动升级期限 | 电影/剧集追踪期限、完结后的处理 |
| 站点与搜索 | 实际站点选择、请求预算等高级项 |
| 等待与更换版本 | 观察、入库后再查、下载中更换条件；0 的语义保留 |
| 媒体库与整理路径 | 已有共享范围、映射、规则的维护 |
| 扫描与恢复 | 重新扫描和恢复相关设置 |
| 清理权限 | 成功后/放弃后/下载器处理等独立授权 |
| 安全与容量 | 并发、容量和保留策略 |
| 榜单与 RSS | 自部署来源、筛选与试读 |
| AI 名称辅助 | 连接、提示词、预算 |

高级诊断、迁移回执、历史恢复入口保留，但不是首次配置所需的主流程。部分罕见高级对象仍使用 Field/Record；本轮没有声称所有高级配置都已完成专用控件设计。
